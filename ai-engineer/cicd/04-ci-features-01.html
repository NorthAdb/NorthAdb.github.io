是什么

在 A 架构机器上，编译出跑在 B 架构上的程序。
例：在 x86_64 Linux / CI Runner 上，用 ARM 工具链编出板端固件。

名词 含义
主机（host） 执行编译的机器 / 容器（多为 x86）
目标（target） 程序真正运行的芯片 / 板子
工具链 交叉编译器、sysroot、链接库一套

固件一般不在 PC 上跑。 编译机只负责「编对 + 传出」；能否起来看板端安装测试。

和 CI 的关系（记这条链路）

Docker 工具链镜像
  → checkout 代码
  → 交叉编译
  → 上传到 HTTP / 制品库
  → 板端下载、刷机、安装测试
  • Job 用 Docker 镜像封装交叉工具链 → 环境统一
  • 制品是板端包 / 固件（按 Commit SHA），不是宿主机可执行文件
  • PC / Runner 不跑固件；硬件测试架或板子从 HTTP 拉包验证

口述（通用开发）：

「交叉编译是嵌入式常见需求；CI 用带工具链的镜像编目标产物，再归档/上传，保证构建环境一致。」

口述（嵌入式加深）：

「Runner 拉工具链 Docker，checkout 后交叉编译固件，按 SHA 上传到 HTTP 或制品库；测试架下载刷机做安装冒烟。固件不在编译机上跑。」

动手 Demo（推荐）

目录：demos/cross-compile/

模拟：Docker → 交叉编译 → 上传 HTTP；板端安装测试只说明、不连真板。

cd demos/cross-compile
./run_demo.sh          # WSL / Linux
# 或 .\run_demo.ps1    # Windows + Docker

通用岗掌握到什么程度？

  • 知道定义、知道用 Docker 封装工具链
  • 知道产物去向：制品库 / HTTP → 板端测，而不是 PC 执行
  • 不必背具体 arm-linux-gnueabihf-gcc 参数
  • 面试若不问嵌入式，一句带过即可
