5. GitLab CI 自测题

建议：先闭卷，再对答案。口述题录音一遍。

AI AI Agent 面试宝典 CI/CD 面试突击 阅读约 1 分钟
On this page

建议：先闭卷，再对答案。口述题录音一遍。

A. 填空 / 选择

A1. 流水线配置文件通常叫 __，放在仓库里表示「代码即流水线」。

A2. 真正执行 Job 的组件是 __；Docker 执行器的三个优势是：__、__、__。

A3. 控制 Job「什么时候跑」的关键字是 __；保存测试报告用 __；加速 pip 安装用 __。

A4. pytest 非 0 退出码会导致 Job（成功 / 失败）。

A5. needs 的主要价值是 __。

B. 简答

B1. 写出 MR smoke 与 main Gate1 两条 Job 的 rules 条件（概念即可）。

B2. Cache 和 Artifacts 各举一例内容，并说明目的差异。

B3. 标准 CI 流程从 MR 到报告归档，按顺序列 6~8 步。

C. 口述题（必练）

限时 1 分钟：

从开发者开 MR，到测试报告归档，中间用上：Pipeline、Stage、Job、Runner、Docker 执行器、pytest、artifacts、rules。

参考答案

A

题 答案
A1 .gitlab-ci.yml
A2 GitLab Runner；干净统一环境 / 封装工具链 / 不污染宿主机
A3 rules；artifacts；cache
A4 失败
A5 缩短流水线总时长（精细依赖、尽早并行）

B（要点）

B1

  • MR：merge_request_event
  • Gate1：main + push

B2

  • Cache：.venv / pip 缓存 → 加速
  • Artifacts：report.xml / 安装包 → 留存与下载

B3

MR 触发 → 拉代码 → Lint → 静态扫描 → 单测 → 编译构建 → 产出制品 → 报告归档

C（示例）

开 MR 触发 Pipeline。Runner 用 Docker 执行器跑各 Stage 里的 Job。MR 相关 Job 靠 rules 匹配，script 里跑 pytest smoke。测试报告用 artifacts 归档；失败则 Job 红，合并门禁拦住。
