01 · 进程排查

场景：CI Job 卡住、CPU 打满、僵尸进程、找不到谁占端口。

AI AI Agent 面试宝典 CI/CD 面试突击 阅读约 1 分钟
On this page

场景：CI Job 卡住、CPU 打满、僵尸进程、找不到谁占端口。

1. 列出与定位

命令 用途
ps aux 全量进程（USER/PID/%CPU/%MEM/CMD）
ps -ef --forest 父子树，看谁拉起谁
pgrep -af keyword 按命令行关键字找
pidof python 按可执行名找 PID
pstree -p 树形（更直观）

技巧：ps aux \| grep -i [p]ytest 用方括号，避免 grep 自己进结果。

2. 资源占用

top -o %CPU          # 按 CPU 排；按 M 看内存视图（top 内）
# 或
ps aux --sort=-%cpu | head -15
ps aux --sort=-%mem | head -15

单进程持续采样（装了 sysstat）：

pidstat -u -p <pid> 1 10     # CPU
pidstat -r -p <pid> 1 10     # 内存

读 /proc（无额外工具时）：

cat /proc/<pid>/cmdline | tr '\0' ' '; echo
cat /proc/<pid>/status | egrep 'Name|State|VmRSS|Threads'
ls -l /proc/<pid>/fd | wc -l          # 打开 fd 数（泄漏线索）

3. 进程状态（STAT）

字母 含义 处理
R 运行/可运行 正常
S 可中断睡眠 等 I/O 或事件
D 不可中断睡眠 常卡磁盘/NFS，难杀
Z 僵尸 父进程未 wait；处理父进程
T 停止 被 SIGSTOP / 调试

4. 信号与结束

kill -15 <pid>       # SIGTERM：请求优雅退出（优先）
kill -2 <pid>        # SIGINT：等同 Ctrl-C
kill -9 <pid>        # SIGKILL：强杀（可能留锁/脏文件）
kill -0 <pid>        # 测进程是否还在（不发真实信号）

笔试话术：先 TERM 再 KILL；写脚本用 timeout 30s cmd 防挂死。

5. 谁占了端口 / 文件

ss -lntp | grep :8080
lsof -iTCP:8080 -sTCP:LISTEN
lsof /path/to/file
fuser -v /path/to/file

6. CI 常见排查顺序

1. Job 日志最后一行停在哪
2. Runner 机器: ps / top 看是否还有 pytest、docker、编译进程
3. 看是否 D 状态（磁盘）或等锁
4. 子进程是否孤儿 / 僵尸
5. 再决定 kill / 重启 Runner / 清 workspace
