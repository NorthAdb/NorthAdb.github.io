包地图与依赖

monorepo 分层

N 学习 Pi 导读 阅读约 10 分钟
On this page

基准：上游 1.0.2（2026-10-04）。 相对 0.99：packages/agent 不再包含 Harness；packages/session-backends 已删除，SQLite 收进 pi-durable。codemode / mcp 仍是独立包。

Monorepo 一览

根目录 package.json 的 workspaces 是 packages/*，外加若干 example 扩展包。没有 session-backends。

目录 npm 名 一句话
packages/chord @earendil-works/chord 应用组合运行时：服务、复制状态、RPC、插件底座
packages/telemetry @earendil-works/pi-telemetry 厂商中立的遥测契约、参考适配器与 schema
packages/tui @earendil-works/pi-tui 终端 UI：差分渲染，不依赖 AI
packages/ai @earendil-works/pi-ai 统一多厂商 LLM（stream、tools、模型目录）
packages/durable @earendil-works/pi-durable 持久化会话 / 任务 / 文档运行时
packages/agent @earendil-works/pi-agent-core 只有循环：Agent、agentLoop、proxy、类型。1.0 起不含会话和压缩
packages/protocol @earendil-works/pi-protocol 客户端 / 服务端协议契约
packages/client @earendil-works/pi-client 协议客户端
packages/server @earendil-works/pi-server 实验性服务端封装
packages/codemode @earendil-works/pi-codemode QuickJS 沙箱里跑 JS，唯一能力是调用注入的工具
packages/mcp @earendil-works/pi-mcp 独立 MCP 客户端（stdio / Streamable HTTP / OAuth）
packages/coding-agent @earendil-works/pi-coding-agent 编码 Agent CLI / SDK / 扩展生态（产品包）。日常会话在这里，不在 durable
packages/evals @earendil-works/pi-evals 内部行为评测

packages/session-backends、packages/agent/src/harness、packages/agent/docs/ 都是 1.0 之前的路径，当前仓库里没有。

依赖方向（必须记住）

chord / telemetry / tui     ← 叶子
codemode ──► quickjs-wasi
mcp      ──► cross-spawn

ai       ──► telemetry
durable  ──► chord, ai
agent    ──► ai                 ← 1.0 起不再依赖 chord / telemetry
protocol ──► chord
client   ──► chord, protocol
server   ──► chord, protocol    ← 不再依赖 agent

coding-agent ──► chord, agent, ai, tui, codemode, mcp

一句话：tui / ai / agent 是被复用的底座，coding-agent 是产品装配点。 durable 是旁边的实验运行时，产品包的 dependencies 不引用它。mcp 与 codemode 也不依赖 agent，可以单独嵌进别的 Node 应用。

构建顺序（根 package.json 的 build 脚本）：

chord → tui → telemetry → codemode → mcp → ai → durable → agent
      → protocol → client → server → coding-agent

为什么这样排：ai 先于 agent 和 durable；agent 只被 coding-agent 在运行时需要，但构建上排在 protocol 之前；产品包最后。

每层该解决什么问题

pi-ai

  • Provider 差异屏蔽（OpenAI / Anthropic / Google / Bedrock / Azure / …）
  • 流式响应与 tool call 结构统一
  • 模型目录（生成数据在 src/providers/data/，gitignore，需 hydrate / generate）

学习者：先会 createModels + streamSimple，不必先懂全部 provider。

pi-agent-core

  • Agent / agentLoop：多轮工具循环
  • 事件：agent_start / turn_* / message_* / tool_execution_*
  • prepareRequest（每次请求前）与 finishTurn（回合后决定停或再来一轮）
  • AgentMessage vs LLM Message（convertToLlm）
  • 不含会话文件、压缩、技能。那些在 coding-agent；可恢复运行时在 durable

pi-tui

  • 组件、requestRender、差分更新、overlay
  • coding-agent 的交互模式建立在这之上
  • 也可被 extension 用来做自定义 UI

pi-codemode

  • 在 QuickJS（WASI）沙箱里执行模型写的 JavaScript
  • 沙箱内唯一能力 = 调用宿主注入的工具：没有文件系统、网络、进程
  • 脚本侧 API：searchTools() / describeTool() / describeNamespace() / ALL_TOOLS
  • 解决的问题：把「几十个工具」从模型上下文里挪进脚本——MCP 工具默认就走这条路

pi-mcp

  • 独立 MCP 客户端：JSON-RPC 2.0 over stdio 与 Streamable HTTP
  • OAuth：动态客户端注册、mcp-auth.json 存 token、过期刷新
  • 覆盖 tools / resources / prompts 原语与进度通知
  • 不依赖 Pi，可嵌进任何 Node 应用

pi-coding-agent

  • CLI 入口、设置、鉴权、资源发现（extensions / skills / prompts / themes / mcp.json）
  • AgentSession：产品级会话门面
  • 四种模式（interactive / print / json / rpc）+ SDK
  • 内置扩展装配点：src/extensions/index.ts:7-14。llama.cpp 只是 builtin；codemode / tool-search / mcp 同时是 replaceable

chord / durable / protocol / client / server / telemetry

  • chord：应用组合与复制状态底座。durable、protocol、client、server、coding-agent 依赖它。agent 循环包不依赖它
  • durable：实验性持久化运行时。SQLite 与 JSONL 存储在包内（storage/sqlite/node、storage/jsonl）。API 会变
  • protocol + client + server：进程间协议三件套。server 不再依赖 agent
  • telemetry：只放契约与 schema，不绑定任何厂商。agent 循环包不依赖它

版本策略

各包 lockstep 同版本号。当前是 1.0.2，见任意 packages/*/package.json 的 version。

和「为什么适合二次开发」的关系

分层让二次开发有三种深度：

深度 改哪里 典型场景
浅 只加 coding-agent 资源（skill / extension / package） 工作流定制
中 依赖 pi-ai / pi-agent-core / pi-mcp / pi-codemode 写自己的宿主 嵌入应用
深 fork 改某层并保持接口 协议 / 循环语义创新

大多数人应停在「浅」；Pi 的设计就是让「浅」足够强。
