会话与上下文

session、分支、compaction、AGENTS.md

N 学习 Pi 导读 阅读约 3 分钟
On this page

Session（会话）

  • 交互过程落到会话文件（格式见 docs/session-format.md）
  • 可 -c 继续最近会话、-r 选择恢复、--fork 分叉
  • --no-session 临时模式

会话不只是「聊天记录」，还包含树/分支、compaction 相关条目等，使 Agent 工作可恢复、可分享（OSS session 数据集文化）。

Branching（分支）

可在会话树上导航、从中间节点长出新分支。
用途：试探两条实现路径、回滚到工具调用前等。

文档：docs/sessions.md。

Compaction（压缩）

上下文太长时，用摘要等策略压缩，保住「还能继续干活」的记忆。
也可自定义 compaction（扩展例子：custom-compaction.ts）。

文档：docs/compaction.md。

Context files

默认发现 AGENTS.md / CLAUDE.md（全局与项目祖先链）。
本仓库根目录就有 AGENTS.md——这是「项目规则进系统上下文」的标准做法。

可用 --no-context-files 关闭。

Skills 与渐进披露

  • 系统提示里通常只有技能名称与描述
  • 完整 SKILL.md 在需要时通过 read 或 /skill:… 进入上下文

避免一上来把所有手册塞进窗口——这是 Agent Skills 的核心教学点。

Scoped models

--models / enabledModels 把可用模型限制到子集；/scoped-models 与 ctx.scopedModels（扩展 API）暴露同一集合。

空列表通常表示「未配置范围 = 全部可用」。

消息队列（交互模式）

运行中可排队：steering / follow-up 等（产品 README 的 Message Queue 节）。
对应 agent-core 的队列语义——UI 与运行时对齐。

学习者实验建议

  1. 开会话改一个文件，退出，用 -c 继续，观察是否记得上下文
  2. 故意把对话拖长，触发 / 手动 compaction，看摘要如何出现
  3. 在项目放一小段 AGENTS.md，问模型「你读到了什么项目规则」
  4. 导出或打开 session 文件，对照 session-format.md 认条目类型
