四种运行模式

TUI / print / JSON / RPC

N 学习 Pi 导读 阅读约 3 分钟
On this page

Pi 同内核，四种（加 SDK）出口——这是「适合二次开发 / 集成」的关键设计。

对照表

模式 如何进入 模块 用途
Interactive (TUI) 默认 pi modes/interactive/ 日常人机结对
Print -p / --print；管道 stdin 也会走向 print modes/print-mode.ts 一次性任务、脚本
JSON --mode json 同上 结构化事件流，便于宿主解析
RPC --mode rpc modes/rpc/ 用 JSONL 命令/事件做进程集成
SDK 代码里 createAgentSession() core/sdk.ts 嵌进 Node 应用（无 CLI）

Interactive

  • 完整编辑器、slash 命令、快捷键、消息队列
  • 依赖 pi-tui 差分渲染
  • 1.0 起默认全屏。要原来的终端滚动缓冲，把设置 tuiMode 设为 "regular"，或传 --tui-mode regular
  • 扩展可加自定义 header/footer/overlay/编辑器行为

适合：学习产品、写扩展、日常开发。

Print / JSON

  • 非交互跑完退出
  • JSON 模式输出事件，便于日志与自动化
  • 官方文档：docs/json.md、docs/usage.md

适合：CI 片段、批处理、简单自动化（复杂集成更看 RPC/SDK）。

RPC

  • stdin：JSONL 命令
  • stdout：JSONL 事件
  • 官方：docs/rpc.md
  • 例子：examples/rpc-extension-ui.ts 等

适合：IDE 插件宿主、外部编排器、不想链进 SDK 打包时。

SDK

阶梯例子在 examples/sdk/：

  1. 01-minimal — 最小会话
  2. 02-custom-model — 模型
  3. 03-custom-prompt — 提示
  4. 04-skills — 技能
  5. 05-tools — 工具
  6. 06-extensions — 扩展
  7. …
  8. 12-full-control — 高度定制
  9. 13-session-runtime — runtime 级控制

适合：做自己的 Agent 产品壳、评测、内部平台。

设计收益

同一 AgentSession
    ├─ TUI 渲染事件
    ├─ JSON 打印事件
    ├─ RPC 翻译事件
    └─ SDK 订阅事件

二次开发时优先问：我是缺 UI、缺协议，还是缺循环？

  • 缺 UI → extension / 自建前端 + SDK
  • 缺协议 → RPC/JSON
  • 缺循环语义 → 才考虑动 agent-core
