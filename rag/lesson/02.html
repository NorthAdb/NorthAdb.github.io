首页/ RAG/ 第 02 节

原始资料的筛选与清洗

第 02 节约 35 分钟本节自测

脏数据四宗罪实验：页眉页脚、样板句、断行、文档级重复如何污染检索；v3：真实污染清单与清洗评估四步。

本节任务：理解"垃圾进垃圾出"在 RAG 里长什么样，并能自己写出/改造一个 可开关的清洗器——它是全课性价比最高的优化：不花一分钱 API，只改一个函数。

课程地图上的位置：Layer 1（知识工程）第一课。上一节 01 全景； 下一节 03 切分。清洗的对象是 loader.py:27 产出的 RawDoc（1 篇文件 = 1 个文档， doc_id = 文件名，checksum = 内容 sha256 前 16 位——checksum 可以理解为"内容指纹"： 由全文算出的一段短编号，内容一变它就变，后面靠它发现"源文件改了但索引没更新"， 见 playground/ingest/loader.py:17-26）。

2.1 核心原则：存进去 ≠ 可以被可靠利用

原始文档 → Chunk → Embedding → 向量库      ← 看起来完成了 RAG
    ↓ 但原始数据里有：
冗余 / 噪声 / 重复 / 页眉页脚 / 表述不一致 / 缺乏结构
    ↓ 结果：
垃圾进，垃圾出。检索层救不回脏数据。

"Context 很大 ≠ 知识已经组织好了"——100 个案例直接塞进去，模型看到的是 100 条 流水账，而不是"72% 发生在高并发"这种提炼后的知识。清洗就是提炼的第一步。

2.2 实验设计：故意把语料弄脏

scripts/make_dirty.py:23 的 dirty_text() 把 16 篇干净语料污染成 data/raw_dirty/， 模拟真实抓取/导出场景的四类污染（污染模板在 make_dirty.py:18-20）：

污染类型 具体做法 对应真实场景
① 页眉页脚 每页插入手册页眉、页码、版权行、保密声明 PDF 解析导出
② 样板句重复 同一句免责声明插入每篇 3 次 网页爬取的公共模板
③ 断行与符号拆散 "AVX-512" 被拆成 "AVX-512 -" OCR / 复制粘贴
④ 文档级重复 把 avx2.md 的 5 个段落复制进 avx.md 多来源重复收录

为什么"故意弄脏"是正规做法？ 因为消融实验需要受控变量：干净/脏两版语料 除污染外完全相同，指标差异才能归因于污染本身。这比"在网上随手抓点脏数据"科学得多。

2.3 清洗器代码逐段走读（playground/ingest/cleaner.py）

先看一眼真实效果（本机对 data/raw_dirty/avx.md 跑 clean_text 的前后对比， 你现在就可以用 2.4 的命令复现）：

清洗前（脏）：
====== Intel® 64 与 IA-32 架构软件开发者手册 · 卷 1 · 第 180 页 ======   ← 页眉
版权所有 © 2026 保留所有权利    保密声明：未经许可不得复制本文档内容      ← 版权行
# AVX：256 位向量与三操作数
注意：所有性能数据基于实验室环境，实际结果可能因配置不同而有所差异。      ← 样板句（×3）
## AVX（2011，Sandy Bridge）
AVX（Advanced Vector Extensions）把 SIMD 寄存器宽度……
…（文末还有"返回顶部 | 上一页 | 下一页"页脚）

清洗后（净）：页眉、样板句、版权行、页脚全部消失，正文原样保留
# AVX：256 位向量与三操作数
## AVX（2011，Sandy Bridge）
AVX（Advanced Vector Extensions）把 SIMD 寄存器宽度……

清洗器全文只有 71 行，但每个决策都值得讲。先是两类特征的定义 （cleaner.py:16-27）。正则（regex，下段代码的主角）是一种"描述文本模式" 的小语言：^=+.*=+$ 读作"行首若干个 = 、中间任意内容、行尾若干个 ="—— 清洗规则的主要载体就是它：

# 典型页眉页脚 / 版权行（行级特征）——每条是一个正则
_HEADER_FOOTER_PATTERNS = [
    re.compile(r"^=+.*=+$"),                          # ===== 页眉线 =====
    re.compile(r"^.{0,4}\d{1,3}\s*$"),                # 左侧行号 / 页码
    re.compile(r"版权所有|保留所有权利|All rights reserved", re.I),
    re.compile(r"保密声明|未经许可|不得复制", re.I),
    re.compile(r"^返回顶部$|^目录$|^上一页|^下一页"),
    re.compile(r"软件开发者手册.*卷", re.I),
    re.compile(r"^\s*[-—–]{3,}\s*$"),                 # 分隔线
]
_BOILERPLATE = re.compile(r"注意：所有性能数据基于实验室环境[^。]*。")   # :27

注意 search 不是 match（cleaner.py:37）：any(p.search(line) ...) 允许 模式命中行中任意位置——页码行用 ^...$ 锚自己收紧，宽泛模式（版权词）靠正则 本身控制误伤。这是"宁可正则写得严，不用宽松匹配兜底"的取舍：误伤正文的清洗 比漏掉的页眉更危险。

主函数 clean_text（cleaner.py:30-60）三步，每步独立开关：

def clean_text(text, *, strip_headers=True, dedup_lines=True, normalize=True):
    # 1) strip_headers（:34-41）：逐行过 _HEADER_FOOTER_PATTERNS，命中即丢；
    #    再用 _BOILERPLATE.sub("", out) 整段删样板句
    # 2) dedup_lines（:43-52）：相邻重复行只保留一次——
    #    页眉/导航最常见的重复形态是"连续 N 行一模一样"
    # 3) normalize（:54-58）：
    #    \u00a0 → 空格         不换行空格（网页复制常见）
    #    [ \t]+ → " "          折叠空白
    #    (\w)-\s*\n(\w) → 拼回  英文断词连字符（"AVX-\n512" → "AVX512"）
    #    \n{3,} → \n\n         折叠空行

文档级去重是另一个函数（cleaner.py:63-71）——用 checksum 判重，整篇重复只留一份：

def doc_level_dedup(docs):
    seen, out = set(), []
    for d in docs:
        if d.checksum in seen: continue
        seen.add(d.checksum); out.append(d)
    return out

注意清洗的三个层次（第 9 节会补全这张表）：

层次 时机 对象 本节实现
文本级 清洗时 这一页的页眉/断行 clean_text
文档级 清洗时 这一整篇是重复的 doc_level_dedup
块级 装填时 同一内容被多块收录 第 9 节

2.5 实验 2：脏语料到底伤检索有多深

[!NOTE] 名词速查（本节表格需要，正式讲解在后面的课程） 对刚学完清洗的你来说，下面这张结果表里有四个"还没讲到"的名词。 先混个脸熟，每个都标注了正式登场的节号——现在只需要记住最后一行的读法：

名词 一句话解释 正式登场
Dense（稠密/向量检索） 把问题和文档都变成向量，比"意思像不像" 第 4 节
BM25（稀疏/关键词检索） 数关键词对没对上，看"字面对得上吗" 第 5 节
Hybrid（混合检索） 上面两路都跑，把结果融合起来 第 6 节
MRR@5 "正确答案排第几"的指标：第 1 名 1 分、第 2 名 0.5 分、第 5 名 0.2 分，没进前 5 记 0，对全部题目取平均（第 1 节 1.5 的指标速查有手算例子） 第 10 节

读表口诀：MRR 越接近 1 越好；Dense / BM25 / Hybrid 是三种不同的检索方式， 各自在干净、脏两套语料上跑同一批题。

2.5.1 这个实验是怎么做出来的

不需要信任何人的转述——整个实验在你本机四步复现，每一步都用到了已学内容：

# ① 生成脏语料：2.2 的四类污染写入 data/raw_dirty/（make_dirty.py 的 dirty_text）
python -m scripts.make_dirty

# ② 建索引：build_index 会建全部 7 套索引，本实验用到其中两套——
#    干净语料 flat500x80 与脏语料 dirty500x80，切分参数完全相同（500x80），
#    唯一变量是"脏不脏"——单变量对照
#    （两个词提前解释：strategy = 索引版本名，一个名字对应一套索引，第 9 节正式讲；
#      切分 = 把长文档切成一块块短文本当检索单元，"500x80"即每块约 500 字、
#      相邻块重叠 80 字——切分本身是下一节的主角）
python -m scripts.build_index

# ③ 跑评测：把第 1 节冻住的金标题，在每个方案 × 每套语料上各跑一遍，
#    算出指标并写报告（run_eval.py 的第 2 组就是本实验）
python -m scripts.run_eval        # → experiments/exp2_cleaning.md + .json

# ④ 或者直接在网站上读：/experiments/exp2_cleaning（重跑后数字会刷新）

评测的题目就是 1.5 节那套金标（23 道可回答题参与指标计算，7 道不可回答题不参与）。 "实验 2"这个名字的由来：run_eval.py 按顺序跑 6 组实验，清洗对照排在第 2 组， 所以报告叫 exp2_cleaning——第 3 节的切分消融、第 6 节的融合对比等都出自同一 命令的不同组。

2.5.2 结果与解读

完整报告见 exp2_cleaning：

方案 MRR@5（干净） MRR@5（脏） 变化
Dense 0.880 0.859 -0.021（相对鲁棒）
BM25 0.808 0.748 -0.060（污染最重）
Hybrid 0.928 0.899 -0.029

（口径：30 题金标中的 23 道可回答题；两套语料切分参数同为 500x80； python -m scripts.run_eval 可复现。）

大白话版结论：靠"意思像不像"吃饭的 Dense 对脏数据相对宽容——页眉和样板句 虽然碍事，但它们的意思跟问题差得远，向量空间里挤不进最前排；靠"关键词对不对得上" 吃饭的 BM25 伤得最重——因为页眉、样板句都是在每篇文档里重复出现的文字， 它们直接把"哪些词重要"的统计带偏了。

为什么 BM25 伤得最重？ 三个机制，每个都能从 2.3 的代码对上（第一次读抓住 "重复出现的文字害了词频统计"这个直觉即可；第 5 节讲完 BM25 后回来重读一遍 会全部通透）。先认识主角 IDF（Inverse Document Frequency，逆文档频率）： 给每个词算的"稀缺度"分——含这个词的文档越少，它越值钱。"的、手册"这类 到处出现的词 IDF 趋近 0（没什么区分度），"STTNI"这种生僻词 IDF 极高 （一锤定音）。BM25 的得分里，IDF 就是"这个词该信多少"的权重（第 5 节逐项拆）：

  1. IDF 污染：页眉"Intel® 64 与 IA-32 架构软件开发者手册"出现在每篇文档 （make_dirty.py:18 的 HEADER 模板），这些高频词的文档频率被抬高 → IDF 被 拉低，真正有区分度的术语被淹没。BM25 的 IDF 是全库统计（bm25.py:39-51 建索引时算好），所以脏一行，全库统计都变形；
  2. 样板句霸榜：重复 3 次的免责声明（make_dirty.py:19 BOILER）在含"性能" 字样的查询里疯狂得分，占掉 Top-K 名额；
  3. 断词失配：查询里的 AVX-512 匹配不上被拆成 AVX-512 - 的正文—— BM25 是精确 token 匹配（bm25.py:29-33 的 tokenize 决定了匹配粒度）， Dense 对这种扰动反而宽容（子词语义还在）。

结论：清洗是性价比最高的优化。 而且 Dense 相对鲁棒这件事提醒我们： 不同检索器对脏数据的敏感度不同——评估清洗效果时要分别测，别只看一路。

2.6 筛选的另一面：不是所有资料都值得入库

清洗解决"已有的资料脏"，筛选解决"根本不该进来的资料"：

  • 过时版本（同一文档的 v1 和 v2 只留 v2，否则两个版本互相打架）；
  • 与业务无关的抓取噪声（导航、广告、cookie 声明）；
  • 无法解析的损坏文件（与其留下乱码块，不如记录后跳过）。

判据一句话：入库前问"这个块将来会被某道问题需要吗？"

2.7 注意事项

  • 清洗规则变了 = 老索引全部作废，必须换新 strategy 重建（第 3、9 节展开）；
  • 正则清洗是领域特定的：本课程的模板针对 Intel 手册风格文档；换一批语料， 第一步是重新收集"这批文档的页眉页脚长什么样"，而不是直接复用模式列表；
  • doc_level_dedup 只对整篇完全相同（checksum 相同）去重——两篇 90% 相同 但有一段不同的文档它管不着，那要靠块级去重（第 9 节）。

2.8 加厚（v2）：MinerU 桌面端实战——PDF 进知识库的完整闭环

前面处理的是 Markdown 语料；真实资料大量是 PDF。MinerU 桌面版 （D:\mineru\MinerU.exe）解析 PDF 后把结果放在 C:\Users\1\mineru\<原文件名>-<uuid>\full.md（含标题层级、表格、图片）。

三步闭环（本机已跑通）

# ① 桌面端：拖入 PDF → 解析（已做 12 份，含一本 Agent 教程的各章）
# ② 桥接：扫描解析结果 → 清洗 → 切分 → 嵌入入库
python -m scripts.ingest_mineru
#    OK strategy=mineru500x80  docs=12 chunks=1336 embedded=1336 in 39.29s
# ③ 检索：Playground 把"语料"切到 mineru、"索引版本"切到 mineru500x80

桥接脚本 scripts/ingest_mineru.py:31 的 discover_outputs() 递归扫描 ~/mineru 下每个解析目录，挑出 full.md 落到 data/mineru_corpus/（:28 的 DEST），然后复用 ingest.build_index(corpus="mineru")——第 2、3 节的 全部管线原样复用，只是换了语料来源，这就是 loader 抽象（load_dir）的回报。

实测提问"什么是上下文工程？它和提示词工程有什么关系？"——Top-3 命中 《第_2_章_上下文工程》，答案带引用、内容准确（rerank 1.8s + LLM 2.3s）。

与主语料的关系：隔离，不是混合

mineru 语料的 corpus 标签是独立的 "mineru"，检索时 meta @> {"corpus":"mineru"} （meta 就是 0.3 名词速查里的"元数据"——每块附带的标签；@> 是 PostgreSQL 的 "包含"操作符，意思是"meta 里含这个标签才入选"，第 9 节展开） 发生在向量检索之前——主语料的金标评测完全不受影响。想混合检索？把 corpus 过滤去掉即可（第 9 节的过滤思想：过滤是检索的一部分，也是隔离的开关）。

桌面版 vs CLI 版的取舍

桌面版（已装） pip 版（pip install mineru）
用法 GUI 拖拽解析 命令行 mineru -p xxx.pdf -o out/
自动化 手动触发，结果目录固定可扫 可脚本化、可挂进 ingest 任务队列
本课程接入 ingest_mineru.py 扫描输出目录 直接改输出路径参数

两者产物格式相同（full.md + content_list.json + images）。先桌面版用起来， 想全自动了再装 CLI 版——桥接脚本不用改，换个输入目录就行。

2.9 动手练习

练习会用到两个操作层面的词，第 0 节 0.3 的名词速查里见过一句话解释， 这里结合 Playground 的界面说清楚（正式讲解在第 9 节）：

  • strategy（索引版本）：同一批文档按一套"清洗 + 切分"参数建成的一套索引。 Playground 左侧有『索引版本 strategy』下拉框，选项名自带参数含义—— dirty500x80 = 脏语料 + 每块约 500 字 + 相邻块重叠 80 字；
  • 语料（corpus）：文档的来源标签，是另一个独立开关——左侧『语料』下拉框 控制"检索哪批文档"。看脏语料必须两处一起切：strategy 选 dirty500x80 （选哪套索引）+ 语料选 dirty（选哪批文档）；只切 strategy 不切语料， 会因为"索引里的块都带着 dirty 标签、过滤条件却是 main"而一条都检不出来 ——这个"两个开关各管各的"的现象，第 9 节会正式解释。
  1. Playground 左侧把『索引版本 strategy』切到 dirty500x80、『语料』切到 dirty，问"SSE4.2 新增的字符串处理指令集叫什么"，观察右侧 Trace 里 BM25 那一路（每条命中带 source 标记，source="bm25" 的就是关键词检索 的结果，名词见 2.5 速查表）里有没有页眉/样板句块；
  2. 切回干净组合对比同一问题：语料 main + strategy flat500x80；
  3. 打开 data/raw_dirty/avx.md，找出被复制的 avx2 段落，思考：重复段落对 "AVX2 有什么新特性"这类查询的 Top-K 会造成什么？
  4. 给 _HEADER_FOOTER_PATTERNS 加一条你自己的模式（比如 ^第\s*\d+\s*页$）， 重跑 python -m scripts.make_dirty && python -m scripts.build_index 对比—— 注意这等于"清洗规则变了"，所以必须换新 strategy 才能干净对比；
  5. 对比"解析质量"：用桌面端分别解析一个纯文字 PDF 和一个复杂排版 PDF（多栏/图表）， 对比 full.md 的标题层级与表格保真度——解析质量决定第 3 节切分的上限；
  6. 把 mineru_corpus/ 里的某篇跑一遍第 13 节的 LLM-as-judge，看 Faithfulness 在"真实 PDF 语料"上的表现是否与主语料一致。

2.10 加厚（v3）：真实语料的污染清单 + 清洗效果怎么评估

真实世界比"四宗罪"更脏

make_dirty 模拟的四类是最低配。真实抓取/导出语料的常见污染，按"检测信号"归档：

污染 典型来源 检测信号 常见处理
页眉页脚/页码 PDF 解析 每块开头重复同一句 行级正则（本节 2.3 的做法）
导航/菜单/广告 网页爬取 短行、链接堆、高频跨文档 抓取时按结构掐掉，事后正则兜底
目录页/版权页 书籍/手册 大量"…… 12"式行 按标题匹配整页跳过
断词/断行 OCR/复制粘贴 行尾"- "、句中孤立单字符 归一化拼回（本节 normalize）
分栏乱序 双栏 PDF 语句跨栏后读不通 解析阶段处理（MinerU 版面分析，2.8）
表格散架 PDF/HTML 表格 单元格各自成行 表格文本化（第 15 节 15.4）

经验法则：拿到新语料的第一天别急着建索引——先抽 10 篇肉眼过一遍，把"重复 出现的行"收集成清洗规则。cleaner.py 那张模式列表就是这么长出来的。

清洗效果怎么评估（四步体检，从便宜到贵）

改了清洗规则，怎么知道"洗好了"而不是"洗伤了"？

  1. 数量体检（秒级）：对比清洗前后的总字符数/块数——变化幅度异常（比如掉了 40%）多半是正则误伤正文，回去查规则；
  2. 单测保护：像 tests/test_core.py 一样，把"页眉必须删、正文必须留"固化成 断言（方法论第 13 节讲）；
  3. 金标对比：干净/脏两版跑 python -m scripts.run_eval——本节 2.5 就是 完整示范；
  4. 抽样人检：随机抽 20 个清洗后的块肉眼读一遍。自动指标会饱和（第 10 节）， 肉眼才能发现"删了不该删的半句话"这类指标看不出的伤。
