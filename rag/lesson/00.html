课程导览：环境、约定与你的 RAG 地图

第 00 节约 15 分钟本节自测

三条主线、钉死的模型参数、目录结构、怎样用这门课；v3：五步学习闭环。

本节任务：把开发环境跑起来，在 Playground 里亲手执行一次完整 RAG——之后 17 节课， 就是在放大镜下重走你今天看到的每一步。

课程地图上的位置：这是起点。上一节：无；下一节：第 01 节 全景复习。

0.1 这门课的三条主线

主线 A：手写一条完整 RAG（第 2-10 节）
        清洗 → 切分 → 嵌入 → 向量检索 → BM25 → RRF 融合 → Rerank
        → 查询改写 → Context 装填 → 生成与拒答 → 评测 → Parent-Child

主线 B：知识库工程（第 2、3、9 节穿插）
        原始资料的筛选清洗、去重、元数据、索引版本管理、增量更新

主线 C：扩展视野（第 11-12 节）
        RAPTOR / GraphRAG / LightRAG 扫盲 + LlamaIndex 框架对照

主线 D（v2 加厚篇，第 13-16 节）：
        评测进阶（LLM-as-judge：用一个 LLM 当裁判给回答打分 + 单测保护）
        极简 GraphRAG（三元组=主谓宾原子事实，多跳=沿关系链走几步）
        查询构造与结构化数据（NL→过滤器 / Text2SQL 思路 / 表格文本化）
        高级范式案例（Self-RAG / CRAG / Agentic：让 RAG 会自我纠错的控制流）

主线 E（产品篇，第 17 节）：
        把以上全部积木装配成 /kb 个人知识库（上传/对话/引用/CRAG）

0.3 已钉死的约定（改任何一项 = 全量重建索引 = 实验不可比）

这些参数全部集中在 playground/config.py 一个文件里，课程所有模块都从它读取：

项 值 定义位置 说明

Reranker BAAI/bge-reranker-v2-m3 config.py:38 不可用时自动降级为词法重排

语料 16 篇 CPU/SIMD + 12 篇图谱短文 config.py:14-16 data/corpus、data/graph_corpus

这张表已经用到了不少后面才细讲的名词。本课程的约定是：每个概念第一次出现， 就给一句白话解释（正式讲解在标注的节）——先混个脸熟：

名词 一句话解释 正式登场
Embedding（嵌入） 把一段文字变成一串数字（向量），意思越接近的文本向量也越接近——机器能"算语义"的数学地基 第 4 节
向量库 / pgvector / HNSW 能存向量、并按"谁离查询向量最近"快速取回的数据库能力：pgvector 是 PostgreSQL 的插件，HNSW 是它的快速近邻索引 第 4 节
Reranker（重排器） 检索先粗排出一批候选，再用一个更精的模型把最相关的顶到前排 第 7 节
切分 / overlap 把长文档切成一块块短文本作为检索单元；overlap 指相邻块互相重复携带一小段结尾/开头，防止关键句恰好被切在边界上 第 3 节
strategy（索引版本） 同一批文档按某套"清洗 + 切分"参数建成的一套索引，用一个字符串命名（如 flat500x80）。切换它 = 换一套索引检索，文档本身不变 第 3、9 节
语料（corpus） 一批用途相同的文档 + 一个来源标签（main=课程主语料、dirty=脏数据对照、graph、mineru、kb），检索时按标签隔离互不干扰 第 9 节
金标集 带"标准答案"的考题集：每道题标注正确答案出自哪篇文档、含哪些关键词，用来给系统打分 第 1 节 1.5
元数据（meta） 附在每块上的标签信息（来自哪篇文档、哪个章节、什么语料），可以拿来过滤检索范围 第 9 节
RRF（融合） 两路检索各排一个名次，按"名次的倒数"相加合并——只看名次、不看分数 第 6 节
Parent-Child 小块用来检索（命中准），命中后取它所属的整节大块送给模型——检索和生成用不同颗粒度 第 10 节
Context 装填 把检索到的块按预算和顺序组装成"参考资料"，连同问题一起送给大模型 第 8 节
拒答 资料里没有答案时，明确回答"资料中没有相关信息"而不是硬编一个 第 8 节

[!IMPORTANT] 为什么钉死在 config？因为换模型 = 换了实验条件。bge-m3 的 1024 维向量与 旧向量不可比，金标成绩会整体漂移——你将分不清"是改动变好了，还是换模型变好了"。 想试新模型？正确姿势是：加新 strategy + 重跑全部实验 + 注明口径（第 3 节细讲）。

0.4 降级路径：外部依赖必须有 Plan B

两把 key 放在项目根目录（不进 git）：dsh.txt（DeepSeek）、bag_m3.txt（硅基流动）。 读取逻辑在 config.py:26-31——环境变量优先，其次 key 文件。

任何一家 API 失效，系统自动切到离线实现，课程功能不中断：

依赖 在线版 降级版 切换逻辑
Embedding SiliconFlowEmbedder（embedder.py:31） HashingEmbedder 词袋哈希投影（embedder.py:99） embedder.py:142 get_embedder() 先探活再选择
LLM DeepSeekLLM（llm.py:21） EchoLLM 抽取式拼接（llm.py:90） llm.py:121 get_llm()
Rerank SiliconFlowReranker（reranker.py:22） LexicalReranker 词法重排（reranker.py:56） reranker.py:92 get_reranker()

表里两个词顺手解释：词袋＝只数"哪些词出现过、各多少次"、完全不管词序的 最朴素文本表示（降级版嵌入靠它模拟）；探活＝发一条真实的小请求，试试 对方服务在不在线。

页面徽章会实时显示当前是 ✓ 还是"降级"（Playground 顶栏 / /kb 工具栏）。 这本身就是第一条重要工程经验：外部依赖必须有降级路径。

0.5 动手：跑一遍全流程

前置：PostgreSQL 已在本机运行（安装与调优见 D:\PostgreSQL\README.md）。

# 1) 初始化表结构（幂等：重复执行安全；顺带建 KB 会话表）
python -m scripts.init_db
#    OK  schema ready  (documents now: 42)
#    OK  pgvector 0.8.0
#    OK  kb tables ready (rg_kb_sessions / rg_kb_messages)

# 2) 生成脏语料 + 构建 7 个索引版本（主语料 4 档切分 + PC + 脏数据 + 图谱语料，
#    约 630 块；首次会调用 embedding API，几十秒）
python -m scripts.make_dirty
python -m scripts.build_index

# 3) 启动课程网站
python -m course.app        # → http://127.0.0.1:8000

三个命令分别对应 scripts/init_db.py:69（main()，执行 scripts/init_db.py:17 的建表 SQL）、 scripts/make_dirty.py:48 与 scripts/build_index.py:18。跑完打开 Playground 页（顶栏第一个黄色按钮），用示例问题提问，把右边的 Trace 从头到尾看一遍 （Trace：右侧那块面板，把一次问答"检索 → 融合 → 精排 → 装填 → 生成"每一步的 中间结果摊开给你看——全课程的可观测枢纽，第 1 节 1.3 正式介绍）： 这门课剩下的内容，就是把 Trace 里的每一层讲透。

[!NOTE] 常见启动问题：① 端口 8000 被占——netstat -ano | findstr :8000 找到 PID 后 taskkill /PID <pid> /F；② 数据库连不上——检查 PostgreSQL 服务与 config.py:46 的 DSN；③ 首次建索引卡住——大概率在等 embedding API，看终端 有无 RuntimeError: embedding API failed，有则说明 key 失效（会自动降级，但向量 是词袋投影，语义检索会失灵）。

0.7 数据库表（记住这四张，后面天天见）

建表 SQL 全在 scripts/init_db.py:17-66，表前缀 rg_（config.py:52）：

表 职责 关键列
rg_documents 文档级元数据 doc_id（=文件名，主键）、checksum（sha256 前 16 位——内容指纹：由全文算出、内容一变它就变，靠它发现"源文件改了但索引没更新"）、corpus（语料来源标签，检索时靠它隔离互不干扰，见 0.3 名词速查）
rg_chunks 切片 + 向量 strategy（索引版本）、embedding vector(1024)、meta jsonb、UNIQUE(doc_id, strategy, chunk_index)
rg_parents Parent-Child 父块 parent_id = doc_id::sec<i>，外键级联删除
rg_embedding_cache 向量缓存 key = sha256(模型+文本)——缓存即"算过的结果存下来复用"，重跑实验零成本
rg_kb_sessions / rg_kb_messages KB 会话与消息 kb/store.py:24-45 独立建表

rg_chunks 上有三个索引（init_db.py:53-58）：HNSW（向量）、strategy B-tree、 meta 的 GIN——分别服务第 4、9 节要讲的向量检索与元数据过滤。（B-tree 和 GIN 是 PostgreSQL 的两种索引类型：前者管普通等值查找，后者管"标签包含"这类 jsonb 查询； jsonb 是 PostgreSQL 存 JSON——形如 {"键": "值"} 的结构化数据——的数据类型。）

0.8 每节课的固定结构

  1. 理论复习——只讲"它解决什么问题"，公式和直觉；
  2. 代码走读——真实源码 + 行号，逐段解释为什么这样写；
  3. 如何运行——终端命令 + 预期输出；
  4. 本机实验数据——来自 experiments/ 的真实运行结果（v1/v2 口径会注明）；
  5. 注意事项——踩过的坑；
  6. 动手练习——去 Playground 或终端亲手做。

0.9 学习闭环：每节课的最小回路（v3 加厚）

内容会加厚、案例会更新，但学法不变——每节课走完这个五步回路，比多读三节课更有效：

① 读      本节正文，抓住"解决什么问题 + 代码怎么对上"
② 做      去 Playground 复现本节声称的现象（左侧调参数，右侧看 Trace）
③ 验      跑本节对应的实验或单测（每节"如何运行"都给了命令）
④ 测      /quiz 本节自测，先回想再翻牌，错题重练
⑤ 记      用你自己的话把"结论 + 一个反例"写进笔记——写不出来 = 没懂

第 ⑤ 步最容易被跳过，也最值钱：能复述结论只是及格，能说出"什么情况下结论 不成立"才算学会。本课程每个结论后面都跟着它的适用边界（如"rerank 没用" 只在 16 篇小语料上成立），照着抄一遍边界也是练习。
