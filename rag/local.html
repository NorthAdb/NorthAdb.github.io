本机才能跑的部分

静态页能读完的部分在课表里。这里只保留必须有进程才能跑的入口。

下面三块是课程网站里真正会算东西的页面。它们在请求进来之后要查 PostgreSQL、算向量、有时还要调用对话模型。GitHub Pages 只分发文件，做不到这些，所以这里不放一个打不开的按钮，只写本机怎么进。

Playground

任选检索方案提一个问题，页面展开每一路命中、RRF 融合、Rerank、Context 装填和引用。启动课程服务后打开 /playground。

个人知识库

上传 md/txt/pdf/docx，多轮对话，回答带编号引用。对应第 17 节。启动后打开 /kb。检索测试台在 /kbtest，只跑检索、不写对话。

快速评测

五个检索方案对同一套金标题跑 Recall / MRR。启动后打开 /eval。实验报告正文已经在这个板块的「实验报告」里，不依赖这次现场重跑。

本机启动

python -m scripts.init_db
python -m scripts.make_dirty
python -m scripts.build_index
python -m course.app

服务起来后浏览器打开 http://127.0.0.1:8000。前提是本机 PostgreSQL 与 pgvector 已就绪，嵌入与对话的密钥按 playground/config.py 配置。密钥不要放进 Pages 仓库。
