零基础把静态网页部署到 GitHub Pages

免费、免服务器、全球 CDN。手把手教你用 GitHub Pages 部署个人博客。

N NorthAdb 2025 年 7 月 15 日 阅读约 6 分钟
On this page

你写好了人生第一个网页，然后呢？部署到哪儿？买服务器太贵，搭环境太麻烦——GitHub Pages 就是为这个场景而生的：免费、无需服务器、自带全球 CDN 和 HTTPS，堪称个人博客与静态站点的最佳起点。你正在读的这个博客，就是跑在 GitHub Pages 上的。

这篇文章完整记录整个流程，跟着做即可。

准备工作

  • 一个 GitHub 账号（没有的话先注册）
  • 本地安装 Git（git --version 验证）
  • 一个纯静态站点（HTML/CSS/JS，无后端）

第一步：创建仓库

有两种玩法，取决于你想要的网址：

个人主页 仓库名必须为 <用户名>.github.io，站点地址是 https://<用户名>.github.io
项目页面 任意仓库名，站点地址是 https://<用户名>.github.io/<仓库名>/

个人博客建议用第一种：一个仓库就是一个站点，网址干净好记。

第二步：推送代码

在本地站点目录里初始化 git 并推送：

# 初始化仓库
git init
git add .
git commit -m "feat: 我的第一个静态站点"

# 关联远程仓库（替换成你的仓库地址）
git branch -M main
git remote add origin https://github.com/<用户名>/<用户名>.github.io.git
git push -u origin main

推送失败？大概率是认证问题。两个解决办法：

  1. 用 HTTPS + Personal Access Token：在 GitHub 生成 token（勾选 repo 权限），推送时用户名填你的 GitHub 账号，密码填 token
  2. 用 SSH：ssh-keygen 生成密钥 → 添加到 GitHub Settings → SSH keys，然后把远程地址换成 git@github.com:<用户名>/<仓库>.git

第三步：启用 Pages

代码推上去之后，打开仓库页面：

  1. 进入 Settings → Pages
  2. 在 Build and deployment 里把 Source 选为 Deploy from a branch
  3. Branch 选择 main（或 master），目录选 / (root)
  4. 点击 Save，等待一两分钟，站点就上线了

也可以完全用命令行完成：

gh api -X POST repos/<用户名>/<仓库名>/pages \
  -f "source[branch]=main" -f "source[path]=/"

启用后访问 https://<用户名>.github.io 即可看到你的站点。

两个容易踩的坑

坑一：.nojekyll 文件

GitHub Pages 默认会用 Jekyll 处理站点，如果你的文件里有 _ 开头的目录（比如 _posts），会被 Jekyll 吞掉。纯静态站点请务必在根目录放一个空的 .nojekyll 文件，明确告诉 Pages「别碰我的文件」：

# Windows 下创建
New-Item .nojekyll
# 或 Linux/macOS
touch .nojekyll

坑二：相对路径

如果站点部署在子路径（项目页面），<link href="/css/style.css"> 这种根路径写法会 404。全部改用相对路径：css/style.css、../css/style.css。这也是为什么我的文章页样式都写成 ../css/style.css。

Tip
💡 小提示：上文 link 标签中的根路径写法是被转义后展示的示例，请勿照抄到真实页面里。

进阶：绑定自定义域名

.github.io 用腻了？可以绑定自己的域名：

  1. 在仓库根目录添加 CNAME 文件，内容写你的域名（如 blog.example.com）
  2. 在域名服务商处添加一条 CNAME 记录，指向 <用户名>.github.io
  3. Pages 设置页会自动识别 CNAME 并签发 HTTPS 证书

整个过程大概 10 分钟，证书自动续期，完全免费。

总结

把静态站点部署到 GitHub Pages 的完整链路是：写代码 → git push → Settings 里点两下。从此以后，每次更新内容只需要 git push，其他什么都不用管。

互联网的尽头是静态托管——只要你的内容不需要服务器，就永远不用操心运维。

现在，去部署你的第一个站点吧。这个博客的每一页，都是这样跑起来的。
