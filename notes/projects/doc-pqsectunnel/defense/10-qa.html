10 — 常见问题（答辩 Q&A）

协议与设计

Q1：为什么从 WireGuard 两次握手改成三次？

答：KEM 模式下 Response 完成后双方已能派生密钥材料，但缺少 Initiator 对 Responder 持有相同密钥的显式确认。Key Confirmation 用新派生密钥 AEAD 加密确认载荷，对应 CONTEXT Key Confirmation 的安全目的。代价是约 0.5 个 RTT（1.5-RTT 总计）。

→ 详见 02、01

Q2：Static KEM 和 Ephemeral KEM 分别干什么？

答： - Static KEM（主套件 ML-KEM-512）：长期身份，ct₁ 对 Responder 静态公钥封装，ct₃ 对 Initiator 静态公钥封装。 - Ephemeral KEM（主套件 ML-KEM-768）：每次握手临时生成 E_i，ct₂ 对 E_i^pub 封装，提供前向安全。

→ 04、CONTEXT.md

Q3：1.5-RTT 是什么意思？

答：Initiator 发 Initiation → 收到 Response → 再发 Key Confirmation。第三条与第二条在时间上部分重叠，整体少于 2 个完整往返。时序图见 docs/1.5-RTT交互时序.png。

→ 02

Q4：MAC1 和 PSK 有什么关系？

答：没有关系。PSK 混入 C/H 链的 mix_psk；MAC1 是 DoS 防护，密钥来自 BLAKE2s("mac1----"‖S_r^pub)，在 receive.c 入口先于 KEM 验证。常见误解见 09 §3。

Q5：mac 参与 Transcript（C/H 链）吗？

答：不参与（KE.md L3）。KE 表格中 mac 步骤是发送侧组包顺序；接收侧先验 MAC 再进 noise.c。

→ 05

密码算法与套件

Q6：为什么选 ML-KEM-512 做 Static、768 做 Ephemeral？

答：答辩主套件 mlkem512-mlkem768-sm4gcm-sm3 体现「身份侧 512、临时侧 768」的组合：Static 钥预置、频繁使用；Ephemeral 每次刷新，可用更高参数。具体安全级别对应 NIST Level 1 / Level 3。

→ 04

Q7：换成 SM4-GCM/SM3 后握手报文变大了吗？

答：没有。握手报文尺寸由 KEM 公钥/密文长度决定（512+768 组合 → Initiation 2068B）。SM4-GCM 密钥 128 bit（AES-256-GCM 为 256 bit），不改变 struct 布局。

→ 04

Q8：RKEM 是什么？你们用了吗？

答：RKEM 是论文提出的 Reinforced KEM 变体，仓库保留源码但默认不链入构建。我们用的是标准 双 KEM（Static + Ephemeral 各一个 ML-KEM），不是 RKEM。

→ CONTEXT.md 边界节

实现与分片

Q9：Initiation 2068 字节怎么过 MTU？

答：编译启用 应用层分片：MAC 算完整包后，按 1400B 切分，每片 8B 头 magic=0x5051。主套件 dmesg 显示 Initiation/Response 各 2 片。Key Confirmation 60B 不分片。

→ 06

Q10：为什么必须 MAC 后再分片？

答：WireGuard 兼容的 MAC1 必须覆盖完整握手 struct。若先分片再算 MAC，接收端无法对重组包做一致验证。

→ 06 §4

Q11：静态 KEM 混链为什么 ct₁/ct₃ 和 ct₂ 规则不同？

答：ct₁/ct₃ 在 mix_kem_ss 前将 shk 覆写为 Hash(ct)；ct₂ 直接用 raw shk₂。与 KE.md L109 脚注一致，是当前刻意实现；未来对齐 spec 属 BREAKING 变更。

→ 09 §2

工程与实验

Q12：build.sh 和 run.sh 有什么区别？

答： - build.sh：编译 .ko、pqst、复制脚本，写 suite_meta.env——造工具箱。 - run.sh：genkey、写 conf、insmod、netns 组网、握手、dmesg——真跑实验。

→ 07

Q13：实验里 cli0_ns 和 srv0_ns 是什么？

答：Linux network namespace，在一台机器上模拟两台独立主机。veth 对连接它们，Underlay IP 10.20.0.x 走 UDP 握手，Overlay 10.0.8.x 走 VPN ping/iperf。

→ 07 §3.2

Q14：怎么判断握手成功？

答： 1. setup_ns.sh 输出 Handshake confirmed after Ns（ping 通 10.0.8.2） 2. dmesg.log 有 completed handshake 和 pqc_fragment: reassembled ... 2068/1916 3. 可选 --with-transfer iperf3 有吞吐量

→ 07、06 §9

Q15：PKI 模式和 random 模式握手有区别吗？

答：协议完全相同。差别仅在 Static KEM 公私钥来自 pqst genkey 还是 X.509 证书库。Ephemeral 仍每次内核随机。PKI 证书签名用 ML-DSA-44，不进 Noise 握手。

→ 08
