Agent 高频面试题全解析：从 LLM 到 A2A 协议

📋 本文八大面试题

  1. 🌟 LLM 和 Agent 有什么区别？
  2. 🌟 Agent 和 workflow 有什么区别？
  3. 🌟 Agent 有什么工作模式？
  4. 🌟 function call 是什么？
  5. 🌟 mcp 是什么协议？
  6. 🌟 skills 是什么？
  7. 🌟 function call、mcp、skills 有什么区别？
  8. 🌟 什么是 A2A 协议？

1️⃣ LLM vs Agent

LLM 的四大弊端

弊端 说明 Agent 的解决
只会说不会做 能力被困在对话框里，无法真正执行 引入工具调用（搜索/DB/API/代码执行）
没有记忆 对话结束一切归零 配备记忆系统（短期+长期）
不会用工具 只能靠训练数据猜 MCP 等标准化协议统一接入
不会规划 被动响应，一问一答 任务拆解/规划能力

一个完整的 Agent = LLM（大脑）+ 规划模块 + 记忆模块 + 工具模块

一句话区分

LLM 告诉你「怎么做」，Agent 直接帮你「做完了」。

2️⃣ Agent vs Workflow

维度 Workflow Agent
谁控制流程 代码（开发者预设） LLM（自主决策）
特性 确定、可预测、可复现 动态、灵活、能适应变化
类比 工厂流水线（每步固定） 项目经理（自己决定怎么做）
token 消耗 省（约 Agent 的 1/4） 高（反复推理）
可靠性 高（易定位问题） 较低（路径难调试）
适用场景 固定步骤、高可靠性（金融/医疗） 开放式、需灵活应对意外

💡 Anthropic 建议：从最简单方案开始，明确需要时才加复杂度。生产中最常见的是混合架构。

3️⃣ Agent 的工作模式

模式一：ReAct（边想边做）

Reasoning + Acting，最经典最基础的模式。三步循环：思考 → 行动 → 观察 → 回到思考。

  • ✅ 透明可审计、灵活适应、通用性强
  • ❌ token 消耗大、可能陷入死循环

模式二：Plan-and-Execute（先想好再做）

两阶段：先列计划，再逐步执行。

  • ✅ 省钱（token 约为 ReAct 的 1/5）
  • ❌ 不够灵活（可加「重新规划检查点」）

模式三：Reflection（做完再检查）

任务完成后自我审查，像「写完文章再通读改稿」。

  • 自我反思：同一 Agent 切换「审查者」角色
  • 双 Agent 对话：一个生成、一个评审（适合代码/法律/学术）

模式四：Multi-Agent（团队协作）

多个专业化 Agent 各司其职（规划/搜集/编码/测试）。主流框架：LangGraph、CrewAI、OpenAI Agents SDK、AutoGen。

⚠️ Anthropic 提醒：不要过早引入多 Agent，一个强大单 Agent 往往够用。

4️⃣ Function Call 是什么？

让 LLM 不仅能生成文字，还能告诉外部程序「我想调用某个函数」。

工作流程四步

  1. 定义函数：用 JSON 描述工具的名字、功能、参数
  2. 模型判断：LLM 分析意图，决定调哪个函数、参数填啥
  3. 执行函数：⚠️ LLM 不自己执行，只输出结构化指令，真正执行的是你的应用程序
  4. 生成回答：真实数据回传 LLM，用自然语言回复用户

解决两个核心问题

  • 什么时候调用：LLM 根据意图自动判断
  • 传什么参数：从自然语言提取结构化参数

📌 Function Call 是 Agent 的「原子操作」，Agent 是 Function Call 的「高级编排」。

5️⃣ MCP 是什么协议？

Model Context Protocol（模型上下文协议），Anthropic 于 2024 年 11 月开源。

称为「AI 界的 USB-C 接口」——把 N × M 的集成问题变成 N + M

三大角色

角色 职责 类比
MCP Host AI 应用本身（Claude Desktop/Cursor/自研 Agent） 电话机
MCP Client 住在 Host 里，负责跟 Server 通信 翻译官
MCP Server 对外暴露工具能力（GitHub Server、Slack Server） 服务台

关键价值

  • 新增服务不用改 AI 应用代码
  • 工具可发现：Agent 启动时自动查询可用工具，运行时动态发现新能力

6️⃣ Skills 是什么？

教 Agent「在什么场景下、按什么方法、遵循什么规范来完成特定任务」的自然语言指令文件（通常是 SKILL.md）。

Skill 结构示例

---
name: Code_Review_Expert
description: 当用户要求进行代码审查时，自动触发此技能。
triggers:
  - "帮我 review 一下这段代码"
  - "代码审查"
---

# 身份设定
你是拥有 10 年经验的资深后端架构师...

# 审查工作流
1. 看结构  2. 查漏洞  3. 审性能  4. 给方案

# 输出规范
专业、直接，输出 Markdown 格式审查报告。

🔧 MCP 给了装满工具的厨房，Skills 是一本菜谱 — MCP 解决「能做什么」，Skills 解决「该怎么做」。

工作方式

Agent 启动扫描 Skills 列表 → 用户请求匹配 Skill → 加载到上下文 → 按 Skill 指令思考行动（可声明 allowed-tools、打包脚本、指导调用 MCP 工具）。

没加载 Skill = 通用能力；加载 Skill = 该领域专家。

7️⃣ Function Call vs MCP vs Skills

统一比喻

把 Agent 想象成新入职员工：

能力 员工类比 技术本质
Function Call 会「打电话的能力」（最基础） API 协议（LLM 输出结构化调用请求）
MCP 公司「通讯录和电话系统」（统一管理联系方式） 通信标准（Client-Server 工具发现/调用）
Skills 「岗位培训手册」（教做事方法和规范） 提示词扩展（自然语言行为指令，加载进上下文）

维度对比

维度 Function Call MCP Skills
解决的问题 LLM 怎么跟函数交互 怎么统一管理大量工具 Agent 怎么获得领域知识
运行位置 你的应用程序中 外部 MCP Server 中 Agent 上下文窗口内
技术本质 API 协议 通信标准 提示词扩展
标准化 ❌ 各厂商格式不统一 ✅ 统一开放标准 ❌ 各平台自有格式

协作关系（分层互补，非竞争）

Function Call（能力层 - 底层基础）
    ↑
MCP（连接层 - 建立在 Function Call 之上，标准化包装）

Skills（知识层 - 不同维度，指导「什么时候调用、用什么策略」）

做饭比喻：Function Call = 会用厨具的能力；MCP = 一个设备齐全标准化的厨房；Skills = 菜谱和厨艺经验。三者结合才能做出好菜。

8️⃣ A2A 协议

Agent-to-Agent Protocol，Google 于 2025 年 4 月发布，联合 50+ 合作伙伴。

为什么需要 A2A？

MCP 解决的是「Agent ↔ 工具」连接，但当企业里多个 Agent（HR/IT/财务，不同框架开发）需要协作时，MCP 管不了「Agent ↔ Agent」的通信。

三大核心概念

概念 说明 类比
Agent Card JSON 格式「智能体名片」，描述身份/能力/擅长的领域 LinkedIn 简历
Task 协作围绕「任务」展开，有完整生命周期（创建→处理→完成/失败） –
Message & Artifact 通过消息沟通过程信息，通过制品传递最终结果 –

A2A vs MCP（横竖互补）

协议 方向 处理
MCP 竖向 Agent → 工具
A2A 横向 Agent → Agent

📌 协议边界：Agent 之间通信走 A2A，Agent 调用工具走 MCP。

A2A 技术特点

  • ✅ 基于 Web 标准（HTTP + JSON + SSE）
  • ✅ 支持异步和长时间运行任务
  • ✅ 模态无关（文本/音频/视频/图像/结构化数据）

🧩 Agent 协议三层结构

Function Call（底层调用能力）
    +
MCP（标准化 Agent ↔ 工具连接，竖向）
    +
A2A（标准化 Agent ↔ Agent 协作，横向）
    =
Agent 技术完整基础设施

三层各司其职、互补共存。

📝 总结速查

问题 核心答案
LLM vs Agent LLM「回答问题」，Agent「完成任务」（加了工具+记忆+规划）
Workflow vs Agent 谁控制流程：Workflow=代码，Agent=LLM 自主决策
工作模式 ReAct 边想边做 / Plan-Execute 先想后做 / Reflection 做后检查 / Multi-Agent 团队
Function Call 让 LLM 输出结构化调用指令，应用程序执行函数（Agent 原子操作）
MCP 统一 Agent↔工具连接，「AI 界 USB-C」，N×M → N+M
Skills 自然语言知识层，教 Agent 怎么做（菜谱 vs 厨房）
三者区别 Function Call=能力层，MCP=连接层，Skills=知识层，分层互补
A2A Agent↔Agent 横向协作协议，与 MCP 竖向互补
