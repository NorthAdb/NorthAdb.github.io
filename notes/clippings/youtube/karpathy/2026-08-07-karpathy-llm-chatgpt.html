Karpathy 深度解析：ChatGPT 这类 LLM 到底是怎么来的

作者：Andrej Karpathy（OpenAI 创始成员、前特斯拉 AI 总监、Eureka Labs 创始人） | 发布：2025-02-05 | 时长 3:31:23 | 事实主干：YouTube 自动字幕（46875 段，全程覆盖） 证据等级：youtube-auto-subtitles 主题：LLM 训练全栈科普——从互联网数据到 ChatGPT 助手的完整流水线 + 模型的"心理学"。

一句话总论

LLM = 用神经网络做"下一个 token 预测"。训练分三大阶段——预训练、监督微调（SFT）、强化学习（RL）——恰好对应教育的三件事：读课本、看例题、刷练习题。 当你跟 ChatGPT 对话时，你其实是在跟一个"OpenAI 标注者的神经网络模拟"说话。

0. 核心框架：完整流水线

预训练（互联网文本）──► 后训练 ──► 推理（部署）
                     ├─ 监督微调 SFT（对话数据，~3 小时）
                     └─ 强化学习 RL（练习题，最新前沿）
  • 预训练：数月、数万 GPU、数百万美元 —— 计算大头
  • 后训练：约 3 小时量级、便宜但极其关键 —— 决定"人格"

1. 预训练数据：下载并清洗互联网

  • FineWeb（HuggingFace 开源数据集，代表生产级做法）：最终仅 44TB 文本 ≈ 15 万亿 tokens——一个硬盘就能装下
  • 起点：Common Crawl（2007 年起爬取互联网，2024 年已索引 27 亿网页）
  • 清洗流水线： | 阶段 | 内容 | |---|---| | URL 过滤 | 黑名单：恶意/垃圾/营销/成人等 | | 文本提取 | 原始 HTML → 纯文本（去导航/CSS/标记） | | 语言过滤 | FineWeb 只保留 >65% 英文（各公司可自行权衡多语能力） | | 去重 / PII 移除 | 地址、社保号等个人身份信息剔除 |

💡 设计取舍：过滤掉西班牙语 → 模型就不擅长西语。FineWeb 偏英文，其模型英文强、其他语言弱。

2. Tokenization：文本如何变成符号

  • 神经网络需要一维符号序列 + 有限符号集；序列长度是"珍贵资源" → 用更多符号换更短序列
  • 字节（256 符号，序列长 8 倍）→ BPE 字节对编码：反复合并高频相邻对、铸造新符号
  • 现代模型词表约 10 万：GPT-4 = 100,277 个符号（tokens）
  • 直观理解：tokens 就是文本的"原子块"（emoji 比喻），例如 hello world = 2 tokens；大小写、空格都会改变切分
  • 工具：https://tiktokenizer.vercel.app/
  • ⚠️ 模型看不到字符，只看 token —— 这是后面所有拼写问题的根源

3. 神经网络 I/O 与 Transformer

  • 输入：token 序列（窗口 0~8000，即上下文长度）
  • 输出：下一 token 的概率分布（10 万个数字）
  • 训练：随机采样窗口 → 让正确 token 的概率上升（loss 下降）→ 反复更新权重，直到输出与训练集统计一致
  • Transformer 内部：token 嵌入 → 注意力块 → MLP 块 → 输出；参数数十亿~近万亿，随机初始化
  • 本质：无状态的固定数学表达式（乘法/加法/指数等）；"神经元"远比生物神经元简单，只是类比

4. 推理：生成 = 掷加权硬币

  • 从概率分布采样下一个 token → 拼接 → 继续 → 自回归生成
  • 系统是随机的：同前缀每次输出不同
  • 生成结果是训练数据的"混音"而非复读（偶尔会原样背出小片段）
  • 用 ChatGPT 时：权重固定，只有推理，不再训练

5. 实例：复现 GPT-2（llm.c 项目）

  • GPT-2（2019）：1.6B 参数、1024 上下文、~100B tokens —— "第一代现代技术栈"
  • 成本变化：2019 年估算 $40,000 → 2025 年 $100~$600（约 1 天）；原因：数据质量 + 硬件 + 软件优化
  • 训练观感：每步 1M tokens / ~7 秒，32000 步 ≈ 33B tokens；loss 单调下降；早期输出乱码 → 后期连贯英文
  • 硬件：8× H100 节点（约 $3/GPU/小时 租用）；英伟达 $3.4T 市值的"淘金热"——所有 GPU 都在干同一件事：预测下一个 token

6. 实例：Llama 3.1 405B base model

  • Base model = 互联网文本 token 模拟器（"给模型上课之前的学渣"）：
  • 不做助手："2+2=？"不会答，只会续写
  • 会背诵维基百科（高质量来源被过采样 ~10 次 → regurgitation），这是预训练副产品
  • 知识 = 有损压缩（zip 比喻）：高频信息记得准，低频信息模糊
  • 2024 大选 → 幻觉出"平行宇宙"（Mike Pence 而不是 JD Vance）
  • 上下文学习（in-context learning）：few-shot prompt 让它学会"翻译官"模式
  • 提示工程实例：把 prompt 构造成"AI assistant 对话网页"，base model 会顺着扮演助手
  • 发布模型需要两样东西：代码（几百行，描述 forward pass）+ 权重（几十亿个数字）

7. 后训练（SFT）：从模拟器到助手

  • 换数据集：互联网文本 → 人工对话（human-assistant 多轮），训练算法不变
  • 对话编码：特殊 token 标记角色轮次（如 <|im_start|> user/assistant）——类似 TCP/IP 协议，各家略不同
  • InstructGPT（OpenAI 2022）开创：人类标注者（Upwork/Scale AI）写 prompt + 理想回答；公司写几百页 labeling instructions（helpful / truthful / harmless）
  • 现代已转向 LLM 辅助合成数据（UltraChat 等数百万对话），但根基仍是人类策展
  • 核心洞察：ChatGPT 背后不是"魔法 AI"——它是 OpenAI 标注者的统计模拟（标注者通常是各领域专家）
  • 例：巴黎 top 5 地标——若该问题在后训练数据集里，你看到的就是标注者的答案；否则是预训练知识+后训练风格的融合

8. LLM 心理学（一）：幻觉与工具使用

  • 幻觉根源：训练集里"who is X"类问题总是被自信回答 → 模型模仿回答的风格而非知识；内部可能有"不确定神经元"，但没接到"说不知道"的输出口
  • 缓解 1（Meta 做法）：LLM 生成问题 → 质询模型 3~5 次 → LLM judge 对比正确答案 → 把答错的题补上"我不知道"作为新训练样本 → 模型学会把"不确定"接到输出
  • 缓解 2（工具使用）：
  • 引入特殊 token（如 <search_start>...<search_end>）
  • 采样器遇到特殊 token → 暂停生成 → 执行工具（Bing 搜索）→ 结果塞回上下文窗口
  • 上下文窗口 = 工作记忆；参数 = 长期模糊记忆
  • 实用建议：让模型总结《傲慢与偏见》→ 记忆模糊；把文本粘贴进上下文再总结 → 精确。和人一样，先重读再总结

9. LLM 心理学（二）：自我认知

  • 没有持久自我：每次对话从零启动，处理完即销毁；"你是什么模型"没有真实答案
  • 默认行为 = 幻觉一个身份（Falcon 自称"OpenAI 的 GPT-3"——因为互联网上这类问答数据太多）
  • 修正身份两种方式： 1. 硬编码数据：OLMo 在 SFT 混合里塞 240 条硬编码问答（"我是 OLMo，由 AI2 开发"） 2. system message：隐藏在上下文里的"隐形 token"，提醒模型身份/知识截止日期

10. LLM 心理学（三）：模型需要 tokens 去思考

  • 每个 token 只有固定、有限的算力（几十~百层 Transformer），无法在单个 token 内完成复杂推理
  • 推论：推理必须摊开到多个 token（逐步中间结果）
  • 这解释了为什么 ChatGPT 答数学题总是"设变量、列方程"一步步来——标注者写答案时就必须给中间步骤
  • 演示：要求"一个 token 内作答"→ 简单题可以、大数字题失败（模型心算 23×177 出错）；正常作答 → 正确
  • 实践铁律：
  • 复杂计算 → use code（Python 解释器 > 模型心算，可审计）
  • 数点 → 模型数不了（点被 token 化成一团），"use code" 拷进字符串调 .count() 即可
  • 拼写 → 模型看不见字符（"strawberry 有几个 r"曾难倒所有 SOTA）；"use code" 完美解决
  • 锯齿智能 / 瑞士奶酪模型：能解奥赛题却栽在"9.11 vs 9.9"（激活里混入圣经经节特征干扰，研究未完全解释）；能力分布有洞，不可全信

11. 第三阶段：强化学习（RL）

  • 学校类比： | 阶段 | 教育对应 | 数据 | |---|---|---| | 预训练 | 读课本内容（知识） | 互联网文本 | | SFT | 看例题（模仿专家） | 人工对话 | | RL | 刷练习题（自己发现解法） | prompt + 标准答案 |
  • SFT 的局限：人类不知道什么 token 序列对 LLM 最优——人类认知 ≠ LLM 认知，我们只能"初始化"模型，它必须自己发现
  • RL 流程（试错/猜测-检查）：
  • 对每个 prompt 采样大量解法（数千~百万条）
  • 在可验证域（数学/代码，答案可自动判分）奖励正确解法
  • 模型在"游乐场"里自己发现对它有效的 token 序列，逐步强化
  • 预训练+SFT 已成熟多年；RL 是 2025 年初最新、最不标准、细节最多的前沿

12. DeepSeek-R1：推理的涌现

  • 里程碑：DeepSeek-R1（2025-01，DeepSeek/深度求索）公开详述 RL 微调，开源权重
  • 定量：数学准确率随 RL 步数持续爬升；response 长度暴涨
  • 定性：出现自我反思（"wait wait... let me reevaluate"）、多角度验证、回溯重试——链式思考是 RL 的涌现产物，无人硬编码
  • 演示：DeepThink 模式输出"思考过程"+"工整答案"（对人类的展示部分 vs 正确性部分分开）
  • OpenAI o1/o3：同为 RL 训练的 thinking model；隐藏完整思维链（防蒸馏风险），只显示摘要
  • 选型建议（2025 初）：thinking 模型对数学/代码强，但知识问答是杀鸡用牛刀——Karpathy 自述 80~90% 场景用 GPT-4o（SFT 为主），难题才上 thinking 模型
  • 其他：Gemini 2.0 Flash Thinking（实验版）；Anthropic 当时还没有

13. AlphaGo：RL 威力的历史先例

  • 同一张图：监督学习（模仿人类棋手）永远超不过顶尖人类（李世石）；RL（自我对弈）能超越
  • Move 37：AlphaGo 下了人类专家仅 ~1/10000 概率会下的棋，事后证明是妙手——RL 能发现人类不知道的策略
  • 类比 LLM：RL 原则上有能力发现"人类从未想到的思考方式、类比、甚至新语言"，但现在还极早期，且只在可验证域
  • 前景：需要为所有知识域编写大规模多样化"练习题"（prompt 分布）——当前前沿研究热点

14. RLHF：不可验证域的 RL

  • 问题：写诗/幽默/摘要无标准答案 → 无法自动打分；人类逐个打分需 10 亿次，不可扩展
  • 核心技巧（间接化）：训练一个 reward model（独立神经网络：prompt + 回答 → 0~1 分）
  • 人类只需对 5 条输出排序（比写理想回答容易得多 → discriminator-generator gap）
  • reward model 学习人类排序 → 变成"人类偏好模拟器" → 之后对模拟器做 RL，成本极低
  • 优点：任意领域可用、模型确实变好、标注任务变简单
  • 致命缺点：reward model 可被游戏化（对抗样本）
  • RL 跑久会钻漏洞："the the the" 被 reward model 打满分
  • 补一条反例还有无穷多对抗样本 → 只能跑几百步就"裁剪"发货
  • 结论："RLHF 不是真正的 RL"——可验证域（正确答案/胜负）无法被欺骗，可以无限跑、发现超人类策略；RLHF 只是个小微调（GPT-4o 也只经历了 RLHF）

15. 未来展望（Karpathy 版"水晶球"）

  • 多模态：音频（频谱切块）、图像（patch）token 化 → 统一 token 流，方法不变
  • Agents：长时运行任务 + 监督；数字世界将出现"human-to-agent 比"（类似工厂的 human-to-robot 比），人变成监督者
  • Computer use：把键盘鼠标控制权交给模型（ChatGPT Operator 早期例子）
  • 测试时训练：目前推理时参数固定，只有上下文里的 in-context learning；上下文窗口是有限珍贵资源，长多模态任务需要新想法

16. 如何跟踪前沿 & 在哪里用模型

  • 跟踪：LM Arena（人类盲评排行榜，但近期被刷榜、不完全可信）| AI News 周报（Swyx，两天一期，全面）| X/Twitter（关注信任的人）
  • 用模型： | 类型 | 去处 | |---|---| | 闭源旗舰 | ChatGPT / Gemini（gemini.google.com, AI Studio） | | 开源权重 | Together AI playground（DeepSeek-R1 全量） | | Base model | Hyperbolic（Llama 3.1 405B base） | | 本地运行 | LM Studio：蒸馏小版 + 低精度量化，MacBook 可跑 |

总结：你在跟谁说话

  1. 你的 query → token 化 → 插入对话协议 → 一维 token 序列
  2. 输出 = 自回归续写 token
  3. 你在跟谁说话：一个"OpenAI 数据标注者的神经网络模拟"（按标注规范回答）；thinking model 更进一步——是 RL 中涌现出的新东西
  4. 使用心态：把它当工具盒里的工具——会随机幻觉、随机犯傻（瑞士奶酪），检查它的工作、验证结果、对最终产品负责
