10 分钟讲透 AI Agent 8 种主流架构

一句话总论

8 种 Agent 架构不是「八选一」。 真实产品通常从 Tools + ReAct 的最小闭环开始，再按任务复杂度逐步叠加 RAG、Memory、Plan、Reflection、多智能体和自主循环。一个 Agent = 模型 + 设计模式 + 运行边界（权限、预算、中止条件、审计）。

学完你应该获得什么

  • 能说出 8 种主流 Agent 架构各自的适用场景、优点和坑
  • 理解「Agent = 模型 + 设计模式 + 运行边界」的三层结构
  • 能根据任务复杂度选择从哪个最小闭环起步、该叠加哪些能力
  • 知道为什么「更自主」不等于「更成熟」——边界比能力更重要

核心模型：Agent 的三层运行系统

把 Agent 看成一个运行系统：左边输入目标、权限和约束；右边输出不只是文字，也可能是工具操作结果；处理结果会回流成为下一轮的输入。

层 回答的问题 对应架构
第一层 下一步怎么做 ReAct、Plan-and-Execute、Reflection
第二层 完成任务需要什么能力 Tools、Memory、RAG
第三层 系统如何扩展运行 Multi-Agent、Autonomous Loop
底座 安全与可靠性 权限、预算、中止条件、审计

真正可靠的 Agent，底部必须加上权限、预算、中止条件和审计——没有边界的自主不是能力，是风险。

8 种架构详解

1️⃣ ReAct — 边做边判断

是什么：Reason + Act 的结合，不断循环「判断下一步 → 调用工具 → 观察结果」三个动作。

例子：制作竞品报告，先发现缺市场数据→去搜索→拿到结果发现两来源数据不一致→继续查证→证据足够后才进入写作。

适用：路线无法提前预判的开放任务。

坑：可能重复用工具甚至死循环，必须设置停止条件（目标完成 / 预算耗尽 / 请求人工）。

一句话：走一步，看结果，再定下一步。

2️⃣ Plan-and-Execute — 先规划再执行

是什么：规划器把目标拆成任务图，执行器按依赖关系逐步完成；每一步把完成状态交给系统。

例子：竞品报告拆成「确定竞品名单 → 收集产品信息 → 比较价格评价 → 生成结论和引用」。

与 ReAct 的区别：ReAct 像一边走一边找路，Plan-and-Execute 像先看地图再出发。某一步被阻塞时，成熟系统重新规划而非死守原计划。

适用：研究报告、软件开发、项目交付等确定性较强的任务。

3️⃣ Multi-Agent — 多角色协作

是什么：主管智能体拆解任务，分给不同专业角色——研究员检索证据、分析师比较数据、撰稿人生成报告、审查员验证事实；所有角色通过共享工作区同步任务状态、中间产物和证据。

适用：确实需要不同专业视角的复杂任务。

坑：Agent 越多≠越好。会增加通信成本、上下文冲突和劳动重复。价值来自有效分工，不是看起来热闹。

4️⃣ Reflection — 检查并改进

是什么：把「生成」和「评价」拆成独立环节。生成端给出候选答案，评价端按明确标准（完整性、准确性、适用性）打分；不达标时生成具体反馈（如「缺少来源」「结论过度」）送回修改，达标后才交付。

适用：报告、方案等可以定义质量标准的任务。

坑：模型自己评价自己可能存在盲区，最好结合外部测试、可观测数据和人工审核，并限制最大反思次数。

5️⃣ Tools — 调用外部工具

是什么：大模型本身只能生成内容，接入搜索、代码执行、系统命令和企业 API 后才会「从会说变成会做」。模型负责选工具和生成参数，网关负责参数校验、权限检查、用量控制。

难点：不是接入多少工具，而是怎么控制副作用——涉及发消息、转账、付款等操作必须加人工审批和审计记录。模型负责决策，工具负责执行。

6️⃣ Memory — 延续历史状态

是什么：工作记忆保存当前任务运行的目标、事实和状态；记忆管理器提取重要信息，经过去重和冲突处理后写入长期记忆（情景记忆、语义记忆、用户偏好规则）。

例子：记住你关注商业模式、喜欢表格、要求所有结论附带来源。

坑：记忆不是越多越好，必须处理过期、错误、隐私和冲突。好的记忆不仅会记住，也知道什么时候该忘记。

7️⃣ RAG — 寻找可信证据

是什么：普通 Agent 检索一次就直接回答；RAG Agent 会自己拆解问题、改写查询、选择数据源、判断是否需要继续搜索。可同时访问公司文档、公开网页和私有数据库，按相关性、完整性和时间进程去重、重排。

例子：两个来源给出的竞品数据不一致，验证器会要求继续查财报或官网公告，而不是随便选一个数字。

上限：RAG 的能力上限很大程度取决于知识库质量、文档质量和引用可追溯性。

8️⃣ Autonomous Loop — 持续推进目标

是什么：用户给出高层目标后，系统保存目标和当前状态，持续循环「观察 → 决策 → 行动 → 评估」，直到完成、暂停或请求人工。

例子：按美洲时区跟踪竞品动态，按计划搜索新资讯、判断哪些变化值得关注、更新报告、重大事件时主动通知用户。

风险：自主程度最高、风险最大。必须设置权限边界、预算上限、最大循环次数、检查点、审计制和人工审批。 一旦目标理解错误，自动循环会持续放大这个错误——自主性越高，停止机制和控制力必须越强。

选型：从最小闭环开始

场景 起步/叠加
需要访问外部系统 Tools + ReAct
回答依赖文档/事实数据 + RAG
任务需要跨会话延续 + Memory
步骤多、依赖明确 + Plan-and-Execute
交付质量波动大 + Reflection
确实需要专业分工 Multi-Agent
已具备权限/预算/终止机制 才开启 Autonomous Loop

这张图越往右上方走，系统的自主性和任务复杂度越高，但每增加一层也同步增加排障成本、控制成本和安全性风险。

真实组合案例：竞品报告

  1. Plan-and-Execute 拆解任务
  2. 主管智能体把任务分给研究员、分析师、撰稿人
  3. 每个角色内部使用 ReAct
  4. Tools 提供实际操作能力
  5. RAG 提供知识支持
  6. Memory 保存会话历史和任务状态
  7. 出稿后 Reflection 做事实审查和反复修改
  8. 底层 Autonomous Loop 设定目标、检查进度，触发预算限制、权限检查和人工审批

关键洞察

成熟的 Agent 不是最自主的 Agent，而是能在明确边界内稳定、可评估、可停止地完成目标的 Agent。

这就是「复杂度之间的真正关系」：8 种模式是互补叠加的积木，不是互斥的选项。

自测题

  1. 8 种架构分别对应 Agent 三层模型中的哪一层？
  2. ReAct 和 Plan-and-Execute 的核心区别是什么？
  3. 为什么说「Agent 越多不代表越好」？
  4. Reflection 架构最大的盲区是什么？如何弥补？
  5. Tools 架构真正的难点是接入工具，还是控制副作用？
  6. 好的记忆系统为什么「知道什么时候该忘记」？
  7. RAG 的能力上限由什么决定？
  8. 为什么 Autonomous Loop 必须设置停止机制？
  9. 一个「只说会做」的 Agent 和一个「真的会做」的 Agent 差在哪？
  10. 如果要做一个需要搜索资料、跨多轮会话、质量要求高的工具，该选哪些架构组合？
参考答案 1. 第一层：ReAct/Plan/Reflection；第二层：Tools/Memory/RAG；第三层：Tools/Autonomous；底座：权限预算审计 2. ReAct 边走边找路（每步决策），Plan-and-Execute 先看地图再出发（先规划后执行） 3. 会增加通信成本、上下文冲突、劳动重复；价值来自有效分工 4. 模型自己评价自己可能有盲区；需结合外部测试、可观测数据、人工审核，限制反思次数 5. 难点是控制副作用（发消息/付款要人工审批），不是接入多少工具 6. 记忆需要处理过期、错误、隐私和冲突；记住一切反而降低检索质量 7. 知识库质量、文档质量、引用可追溯性 8. 目标理解错误时自动循环会持续放大错误；必须用权限/预算/循环上限/检查点/人工审批兜底 9. 差在 Tools（工具调用）——模型只生成内容，工具让它能真正执行 10. Tools + ReAct 起步 → 加 RAG（知识）→ 加 Memory（跨会话）→ 加 Reflection（质量），预算/权限兜底
