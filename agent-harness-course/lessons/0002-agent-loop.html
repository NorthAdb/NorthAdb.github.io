Agent Loop：循环由谁控制

上一课我们说"LLM 是被调用的函数"。这一课看调用它的那个 while 循环——整个 Harness 的心脏，也是你将来自己写 Harness 时要写的第一段代码。

本课核心问题：用户发出一个请求之后，Pi 是如何驱动 LLM → Tool → Observation → LLM 的？循环到底由谁控制？什么情况下结束？

一、这张图要解决什么问题

"Agent 会自己思考"是一种错觉。真相是：一个普通程序里的 while 循环，每轮把 Context 发给模型，模型回一段文本（可能夹着结构化的 toolCall），循环解析后执行工具，把结果追加回 Context，再来一轮。这张图把这个最容易被神化的机制摊开在桌面上。

二、如何从图上读懂 Pi

源码1. 循环由 Runtime 控制。公开入口 agentLoop 在 packages/agent/src/agent-loop.ts:38，真正的双层循环是私有函数 runLoop（:163）：外层 while（:179）处理 follow-up 消息队列，内层 while（:183）处理"本轮还有没有 toolCall / steering 消息"。模型从未持有控制权——它每轮只提交一次"意见书"。

2. 是否执行工具，看 content 里的 toolCall 块。agent-loop.ts:259：message.content.filter(c => c.type === "toolCall")——不是看 stopReason。有 toolCall 就执行；没有，且 steering / followUp 队列也空，就发 agent_end 退出。宿主另有两道刹车：每次请求前的 prepareRequest（:219，含第一轮）可以替换即将送出的上下文；回合结束后的 finishTurn（:286）返回 { action: "end" } 可以在 turn_end 之后停住，不再排下一轮。整批工具结果都带 terminate 时，也会跳过下一次模型调用。

3. 错误不抛出，而是变成消息。工具 throw 被循环捕获，经 createErrorToolResult（agent-loop.ts:905）包成 isError: true 的 toolResult 文本消息回给模型，模型下一轮自己重试。源码还有个精妙细节：stopReason === "length"（:268，函数 failToolCallsFromTruncatedMessage 在 :478）时，所有 toolCall 一律判失败——防止执行参数被截断的命令。

三、新概念的七问：Agent Loop

  1. 解决什么问题？把"一次问答"变成"多步任务"：观察结果 → 再决定下一步。
  2. 没有它会怎样？模型只能一次性凭空猜答案，无法根据工具反馈修正。
  3. 输入是什么？用户 prompt（经 AgentSession 的 steering / followUp 队列调度）。
  4. 输出是什么？一串 AgentMessage（最终出现在会话里）+ 10 种 AgentEvent 事件。
  5. 由谁控制？Runtime 的 while。模型只有"建议权"（发 toolCall），没有"执行权"。
  6. 和前一概念的关系？它是第 1 课 Harness 图里那颗"循环心脏"——Harness 的其他部件都为它服务。
  7. Pi 在源码哪里实现？源码packages/agent/src/agent-loop.ts；有状态封装在 packages/agent/src/agent.ts（steering / followUp / 事件规约）。

# 1.0.2 的最简 Agent Loop（agent-loop.ts runLoop）
while True:                                    # 外层 :179 follow-up
    has_more = True
    while has_more or pending:                 # 内层 :183 toolCall / steering
        context = prepare_request(context)     # :219 每次请求前，含第一轮
        msg = stream_simple(model, context)
        tool_calls = [c for c in msg.content if c.type == "toolCall"]  # :259
        if msg.stop_reason == "length":
            results = fail_all(tool_calls)     # :268 / :478 截断一律失败
            has_more = False
        elif tool_calls:
            results = execute_all(tool_calls)
            has_more = not batch_says_terminate
        else:
            results = []
            has_more = False
        for r in results:
            context.messages.append(r)         # :274 含 isError
        if finish_turn() == "end":             # :286 正常回合可提前结束
            emit("turn_end"); return
    if not follow_ups:
        emit("agent_end"); return

五、这张图在整个体系中的位置

Agent Loop 是课程的"根概念"：第 3 课深入它调度的工具，第 4 课看它每轮送出的 Context 是怎么拼的，第 11 课看它跑一整场真实任务。把这个 while 循环写出来，你就已经有了最小 Harness 的骨架。
