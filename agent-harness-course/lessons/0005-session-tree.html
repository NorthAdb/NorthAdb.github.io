Session：append-only 的历史树

模型每轮都失忆，所以 Harness 必须替它记住一切。这一课看 Pi 的选择：一个 append-only 的 JSONL 文件，条目之间用 parentId 连成一棵树——以及为什么这比 messages[] 好得多。

本课核心问题：为什么 Coding Agent 不应该只维护一个简单的 messages[]，而需要 History Tree？branch / fork / resume 分别是什么？

一、这张图要解决什么问题

messages[] 有三个致命伤：改历史 = 破坏证据（出错了想回溯？没了）；分支 = 复制整段历史（内存与磁盘双倍浪费）；恢复 = 重新序列化一切。这张图展示 Pi 的答案：条目只增不删，parentId 连成树，一个 leafId 指针决定"现在站在哪"。

二、如何从图上读懂 Pi

源码一切皆条目。packages/coding-agent/src/core/session-manager.ts 里，文件头是 SessionHeader（:43），树上的条目联合类型是 SessionEntry（:183）。不只是消息（message），还有 model_change、thinking_level_change、usage、compaction、branch_summary、custom、custom_message、context_edit、label、session_info。配置的演变、压缩事件、扩展的私有状态都被持久化。每个条目带 { type, id, parentId, timestamp }（SessionEntryBase，:57）。

源码分支 = 移动指针。类注释（:977-985）写明 "append-only trees… The 'leaf' pointer tracks the current position. Branching moves the leaf to an earlier entry"。branch(branchFromId)（:1574）只是把 leafId 指回某个祖先——零拷贝；branchWithSummary() 额外落一条 branch_summary 摘要条目；forkFrom()（:1808）才真正把 root→leaf 路径抽成新文件（header 记 parentSession 血缘）。--continue 按 mtime 找最近文件（:1788）重放恢复 model 与 thinking level。

源码投影，不是回放全部。buildSessionProjection() 从 leaf 沿 parentId 回溯到根，处理 compaction 与 context_edit 条目，产出喂给 Agent 的 messages——这就是第 4 课"Context 投影"的来源。

三、新概念的七问：Session Tree

  1. 解决什么问题？持久、可回溯、可分支、可恢复的任务历史。
  2. 没有它会怎样？崩溃即失忆；改提示词重跑只能从头再来；无法安全地"回到三步之前"。
  3. 输入是什么？每一条新事件（消息、配置变更、压缩、扩展条目）。
  4. 输出是什么？投影后的 messages（给 Agent）+ 可 resume 的文件（给人类）。
  5. 由谁控制？SessionManager 编排；写入是 appendFileSync 一行 JSON（:1187）。
  6. 和前一概念的关系？Session 是第 4 课"历史投影"的数据源头——投影是树的一次遍历。
  7. Pi 在源码哪里实现？源码packages/coding-agent/src/core/session-manager.ts（文件在 ~/.pi/agent/sessions/--<编码后的 cwd>--/<时间戳>_<id>.jsonl）。

四、源码映射与心智图

Session = 树
  Entry = { type, id, parentId, timestamp, ... }   # 只增不删
  leafId ──────────► "当前站在哪个条目"             # 一个指针
  branch(id): leafId = id                           # 分支 = 拨指针，零拷贝
  fork():     root→leaf 路径复制成新 .jsonl          # 血缘 parentSession
  resume():   打开旧文件，重放恢复 model/thinking
  projection: leaf→root 回溯 + compaction 替换 → messages

五、这张图在整个体系中的位置

Session 回答"状态存在哪里"。下一课的 Compaction 是这棵树上唯一"改写投影"的合法机制——历史不动，投影被摘要替换。两课合起来才是完整的状态管理。
