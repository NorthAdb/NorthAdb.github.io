五层 Mental Model 与公式的修正

最后一课把 13 课的积累叠成五层——Model / Agent Loop / Runtime / Harness / Environment。每层回答六个固定问题：输入、输出、谁控制谁、数据怎么流、状态在哪、安全边界在哪。然后修正那个著名的公式。

本课核心问题："Agent = LLM + Loop + Harness + Environment" 这个公式成立吗？严格来说应该如何修正？

一、这张图要解决什么问题

你需要一个能在没有 Pi 源码、没有任何 Agent 在场时，依然可以在白板上画出来的模型——用它可以解释你见过的每一个 Agent，也能指导你从零写一个。五层模型就是那个白板。

二、逐层拆解

Layer 1 · Model【推断/业界共识】。输入：一份 Context；输出：token（可能含 toolCall 建议）；控制：被调用；状态：无；安全边界：无——它只是函数。

Layer 2 · Agent Loop【源码：agent-loop.ts】。输入：Context 投影；输出：下一动作（toolCall 或终止）；控制：Runtime 的 while；与 L1 的关系：每轮"送 Context、收 token"。

Layer 3 · Runtime【源码】。Tools（注册/校验/执行）、Context（组装/缓存）、State（会话树）。输入：Loop 的调度；输出：对 L5 的副作用请求与新的 Context；控制：Loop 调度它；状态：Context 与会话树。

Layer 4 · Harness【源码 + 推断】。Skills/Extensions/Compaction/Policy/UI·RPC·SDK。输入：用户与扩展的意图；输出：对 Runtime 的配置与约束、给用户的界面；控制：它拥有整个系统——Loop 是它调的，工具表是它配的，安全策略是它选的。

Layer 5 · Environment【源码：docs/containerization.md + OS】。FS/Shell/Net/Git/容器。输入：工具的副作用请求；输出：观察结果（stdout、文件内容、退出码）；控制：物理世界；状态：一切真实状态；安全边界：真正的边界在这里（第 9 课）。

关键的不对称（图上玫红卡片）：控制流自上而下，数据流自下而上；而 LLM 对 Environment 没有任何直接通路——每一条通往现实世界的路径都穿过 Harness 的手。这是安全的根基，也是"LLM 不是 Agent"的最终形态。

三、公式的修正

"Agent = LLM + Loop + Harness + Environment" 是成分正确、结构错误：它把四个词并列成加法，掩盖了包含与控制关系。严格式应当是：

Agent = Harness( Loop( Runtime( LLM ) ), Environment )
        │        │       │         │        └─ 物理世界：唯一发生副作用的地方
        │        │       └─ 被调用的 token 生成器（无状态）
        │        └─ 拥有控制权的 while 循环（Reason→Act→Observe）
        └─ 拥有整个系统的主体：装配、配置、约束、暴露接口

换句话说：LLM 是被调用的函数，Harness 是调用者。加法公式把"马"和"马具"并排放在了一起；乘法/嵌套式才表达了"谁套住谁"。这也回答了课程开头的问题：为什么 LLM 自己不能成为 Agent——因为在嵌套式里，LLM 甚至不是最外层的任何一个括号。
