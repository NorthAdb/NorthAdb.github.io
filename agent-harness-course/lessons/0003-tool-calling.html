Tool Calling：模型看到什么，Runtime 执行什么

模型"会调工具"是它最容易被误解的能力。这一课沿着一次工具调用的生命周期走一遍：声明 → 调用 → 校验 → 执行 → 回填，看清模型和 Runtime 各自的辖区。

本课核心问题：为什么说工具是"模型上下文的一部分"？tool name、description、input schema、toolCall、toolResult 分别在哪里产生、保存、传递？——模型到底看到什么？Runtime 到底执行什么？

一、这张图要解决什么问题

把"AI 调用了工具"这句模糊的话，拆成一张时序图上的六方协作：LLM、agentLoop、Tool Registry（含校验）、Tool Executor、OS、Context。看完你就会明白：所谓"模型调用工具"，模型只负责生成一段 JSON 建议，剩下的一切都是 Runtime 的事。

二、如何从图上读懂 Pi

源码声明侧（进模型）：每个工具在 packages/ai/src/types.ts:717 定义为 { name, description, parameters(TypeBox JSON Schema) }——注意这个接口没有 execute。这三样会随每次请求发给模型（"本店菜单"）。description 写得好坏直接决定模型会不会正确用这个工具——它是纯粹写给模型看的广告词。

源码调用侧（出模型）：模型输出 { type: "toolCall", id, name, arguments }（types.ts:419）。Runtime 先用 TypeBox 做 validateToolArguments（packages/ai/src/utils/validation.ts:317），再经扩展的 tool_call 钩子（可 block），然后才调用 tool.execute()。源码execute 是 agent 包加的：AgentTool extends Tool（agent/src/types.ts:464，execute 在 :481），真正干活的函数由产品层注入（coding-agent/src/core/tools/tool-definition-wrapper.ts）。

源码结果侧（回模型）：执行产出 AgentToolResult { content, details }，被包成 role:"toolResult" 消息 push 回 Context——工具因此是上下文的一部分：schema 进请求参数，结果进消息历史。输出超限有统一截断（2000 行 / 50KB，tools/truncate.ts:11），截断时附带"如何继续读"的提示。OS 全程只见 Executor，见不到模型。

三、新概念的七问：Tool Schema / ToolCall / ToolResult

  1. 解决什么问题？给受约束的模型一个结构化、可校验、可审计的"动手接口"。
  2. 没有它会怎样？只能靠解析自由文本里的命令，脆弱且危险。
  3. 输入是什么？工具开发者写的 name/description/schema/execute。
  4. 输出是什么？结构化 AgentToolResult（文本/图片 content），错误时 isError=true。
  5. 由谁控制？声明与校验由 Runtime 控制；toolCall 的"意愿"由模型产生；副作用由 OS 发生。
  6. 和前一概念的关系？toolCall 是 Agent Loop 每轮循环的"分流信号"——本课解释这个信号长什么样、怎么被兑现。
  7. Pi 在源码哪里实现？源码packages/ai/src/types.ts:717（Tool）、:419（ToolCall）、packages/agent/src/types.ts:464（AgentTool.execute）。产品注册表有 8 个工具（tools/index.ts:95），默认只启用 read / bash / edit / write（settings-manager.ts:215）。powershell、grep、find、ls 在注册表里，不在默认集合里。

对象在哪里产生存在哪里传给谁
name / description / schema工具作者（coding-agent/tools/*）Tool Registry随请求发给模型

# 一次工具调用的完整旅程
menu   = [{name:"read", description:"...", schema:...}, ...]   # 声明：进请求
reply  = stream_simple(model, context + menu)
call   = reply.content.find(type == "toolCall")                # 模型只产 JSON
args   = validate_tool_arguments(call.name, call.arguments)    # TypeBox 校验
blocked = extensions.emit("tool_call", call)                   # 扩展可拦截
result = registry[call.name].execute(call.id, args, signal)    # 真副作用
result = truncate(result, max_lines=2000, max_bytes=50KB)      # 统一截断
context.messages.append(toolResultMessage(result))             # 回填给模型
