Compaction：状态压缩，而不是删消息

任务越长，Context 越胖，终会撞上模型窗口上限。天真的做法是"删最老的消息"——这几乎必然坏事。这一课看 Pi 怎么做：用 LLM 把旧历史压成一份结构化摘要，历史不动，投影被替换。

本课核心问题：为什么不能简单删除最老的消息？为什么 Compaction 本质上是 State Compression？Session、Context、Compaction 三者如何连接？

一、这张图要解决什么问题

一条真实任务的时间线：read 十几个文件 → 试错三轮 → 终于改对 → 跑测试。到第 40 轮时，最初的目标和中间的教训早已"滚出"模型的注意力。这张图展示压缩流水线：何时触发、在哪里切、怎么摘要、如何持久化、如何重建。

二、如何从图上读懂 Pi

源码触发：留出回复余量。packages/coding-agent/src/core/compaction/compaction.ts:267 的 shouldCompact：contextTokens > contextWindow − reserveTokens。默认 reserveTokens: 16384、keepRecentTokens: 20000（:126-130）。reserve 给模型回复留空间，keep 决定"最近多少内容原样保留"。1.0 起这段代码只住在产品包里，packages/agent 不再有压缩库。

源码切点：绝不切在 toolResult 上。findCutPoint（:468-523）从最新往回累计估算 token，到 keepRecentTokens 预算处取最近的合法切点；isCutPointMessage（:373）规定 toolResult 永远不是合法切点——否则会把 toolCall 和 toolResult 拆散，请求直接被 API 拒绝。这就是"不能简单删最老消息"的第一层原因。

源码摘要：结构化模板 + 迭代更新。SUMMARIZATION_PROMPT（:529）强制输出 ## Goal / ## Constraints & Preferences / ## Progress（Done/In Progress/Blocked） / ## Key Decisions / ## Next Steps / ## Critical Context；已有旧摘要时走 UPDATE_SUMMARIZATION_PROMPT（:562）做增量迭代摘要——这正是"分支摘要/迭代摘要"的落点。产物持久化为 CompactionEntry { summary, firstKeptEntryId, tokensBefore, … }（session-manager.ts:91），投影重建时用摘要替换 firstKeptEntryId 之前的所有条目。

为什么这是 State Compression？因为被压缩的不是"存储"（JSONL 原文永远在），而是"模型可见的工作集"——和操作系统的页压缩/快照同构：持久状态 → 压缩表示 → 模型可见上下文。保留所有历史 ≠ 把所有历史送进模型。

三、新概念的七问：Compaction

  1. 解决什么问题？长任务的上下文耗尽——目标是"忘掉细节，记住意图"。
  2. 没有它会怎样？长任务必然撞窗口上限；硬删消息则目标漂移、重复劳动、API 报错。
  3. 输入是什么？当前投影 + 阈值参数（reserveTokens / keepRecentTokens）。
  4. 输出是什么？一条 CompactionEntry 持久化进会话树 + 压缩后的新投影。
  5. 由谁控制？agent-session.ts 的 _runAutoCompaction（:2747）自动触发（threshold / overflow 两类）；/compact 手动；扩展可用 session_before_compact 钩子接管。
  6. 和前一概念的关系？它是 Session（第 5 课）树上唯一合法的"投影改写器"。
  7. Pi 在源码哪里实现？源码packages/coding-agent/src/core/compaction/compaction.ts（纯算法）+ agent-session.ts:2599-2735（编排）。

四、源码映射与心智图

Old History ─► Persistent State（JSONL，永不改动）
           ─► Compressed Representation（CompactionEntry 摘要条目）
           ─► Model-visible Context（buildSessionProjection 重建）

trigger: tokens > window − 16384
cut:     从最新往回累计 ≥ 20000，且切点不得是 toolResult
summary: LLM 按结构化模板生成；有旧摘要则迭代更新
persist: CompactionEntry { summary, firstKeptEntryId }
rebuild: 投影时用 summary 替换 firstKeptEntryId 之前的一切

五、这张图在整个体系中的位置

Compaction 让"无限长任务"成为可能，是 Harness 区别于"套壳聊天"的标志能力之一。下一课的 Skills 用相反的思路控制上下文：与其事后压缩，不如一开始就别装进来——这就是渐进披露。
