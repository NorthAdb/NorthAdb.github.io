Skills：渐进披露（Progressive Disclosure）

如果用户装了 30 个技能包，每个 2000 字说明，全塞进系统提示词？这一课看 Pi 的答案：常驻的只有"菜单"，正菜按需上。这是上下文工程里最重要的杠杆之一。

本课核心问题：为什么 Skill 不应该一开始就把全部说明注入 Context？渐进披露在 Token 成本、Prompt Cache、可发现性、可扩展性上各赢在哪？

一、这张图要解决什么问题

Traditional 做法：System Prompt 里塞满所有技能文档 + 所有工具文档 + 全部历史。代价是三重的：token 贵、缓存失效快、模型在长文档里"找不到重点"。这张图展示 Progressive Disclosure 的流水线：发现 → 索引 → 只披露目录 → 模型按需自己加载全文。

二、如何从图上读懂 Pi

源码发现与索引。packages/coding-agent/src/core/skills.ts:409 的 loadSkills() 扫描 ~/.pi/agent/skills（用户级）与 <cwd>/.pi/skills（项目级），规则极简：目录里有 SKILL.md 就是技能根，不再下钻（:160）。frontmatter 校验严格：name ≤64 字符小写连字符，description 必填 ≤1024（:92-127）。

源码披露：只有菜单进提示词。formatSkillsForPrompt()（:355）生成一段 XML：

<available_skills>
  <skill><name>…</name><description>…</description>
         <location>/path/to/SKILL.md</location></skill>
</available_skills>

每个技能常驻成本 ≈ 两行字。全文加载没有任何特殊机制——就是提示模型"任务匹配 description 时，用 read 工具读 location 指向的文件"。魔法全部借用了第 3 课的工具循环。disable-model-invocation: true 的技能不进目录，只能 /skill:name 显式调用（不给模型自主触发的权力）。

四笔账：Token Cost（常驻 ≈ 0，触发后才付全文的钱）；Prompt Cache（菜单不变 → 前缀稳定 → 缓存命中）；Discoverability（菜单常在，模型随时能"看到"还有什么可用）；Extensibility（装一个技能 = 丢一个目录进文件夹，零代码）。对比 Traditional 的"全量注入"，四项全输。

三、新概念的七问：Skill / 渐进披露

  1. 解决什么问题？让 Agent 掌握大量可复用的知识与流程，而不用为"可能用不到"预付上下文。
  2. 没有它会怎样？要么技能贫瘠，要么提示词爆炸、缓存失效、模型迷航。
  3. 输入是什么？一个含 SKILL.md（frontmatter: name/description/…）的目录。
  4. 输出是什么？提示词里的 XML 目录条目 + 触发后由 read 工具载入的全文。
  5. 由谁控制？发现与注入由 skills.ts；触发由模型决定（这是与 Extension 的关键区别）。
  6. 和前一概念的关系？Compaction 是"事后瘦身"，渐进披露是"事前不胖"——同一场上下文预算战争的两侧。
  7. Pi 在源码哪里实现？源码packages/coding-agent/src/core/skills.ts；注入点 system-prompt.ts:166 的 skills section。

五、这张图在整个体系中的位置

Skills 是"知识面的扩展"，下一课的 Extensions 是"运行时的扩展"——两者构成 Pi 可扩展性的两翼，也是"Minimal Core"哲学的两大支柱。
